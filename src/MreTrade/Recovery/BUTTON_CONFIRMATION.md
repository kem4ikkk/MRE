# Подтверждение обмена с проверкой версии

Игровое событие `onEffectButtonClicked` передаёт серверу игрока и имя кнопки; идентификатор окна и версия предложения в событии отсутствуют. Поэтому один постоянный `TradeConfirm` не позволяет отличить задержанный клик от нового. Ожидание, повторное открытие окна или простое обнуление подтверждений не решают проблему.

После `/trade accept` сервер открывает окно обоим игрокам. Кнопка `TradeConfirm` фиксирует показанную в UI текущую ревизию и подтверждает только её; текстовых команд для выбора, подтверждения и отмены в игровом потоке нет. Любое изменение предложения увеличивает ревизию, обновляет UI и сбрасывает отметки просмотра и подтверждения обеих сторон. Для подтверждения новой версии нужно снова нажать кнопку после проверки обновлённого окна.

Это снижает риск случайного подтверждения задержанным кликом, но не даёт строгой гарантии: callback `onEffectButtonClicked` передаёт только повторно используемое статическое имя `TradeConfirm`, без ID окна, сессии, ревизии или времени нажатия. Если старый callback придёт после обновления предложения либо после закрытия старого окна и создания новой сессии с теми же игроками, сервер не сможет отличить его от нового клика. Для строгой привязки потребовалось бы клиентское событие с токеном, сессией и ревизией либо иной callback с таким payload.

Модельный тест проверяет обязательность просмотра, сброс отметок просмотра обеих сторон после изменения, повторное подтверждение и отказ для постороннего SteamID. Вызовы модели вроде `Acknowledge` и `Confirm` относятся только к изолированным тестам и отсутствуют как пользовательские команды в игре. Игровые задержанные RPC и два клиента ещё не проверены; описанное выше окно гонки остаётся ограничением протокола. Аварийная сохранность инвентарей остаётся отдельным блокером; включать обмен для ценных предметов нельзя.
