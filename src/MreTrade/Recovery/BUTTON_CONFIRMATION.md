# Подтверждение обмена с nonce

Статический callback кнопки `TradeConfirm` сообщает только игрока и имя кнопки. Он больше не подтверждает обмен. Кнопка UI дополнительно вызывает `InputField.SendOnEndEdit()` для скрытого поля `TradeConfirmToken`; Unturned отправляет серверу `onEffectTextCommitted(player, fieldName, text)` с текстом nonce, который был в поле в момент нажатия.

Сервер выдаёт отдельный случайный nonce каждому участнику. Внутри серверной сессии ticket привязан к `SessionId`, ревизии предложения и поколению открытого UI. Изменение предложения, закрытие UI/переход в редактор, повторное открытие или новая сессия делают прежний nonce недействительным. Ticket потребляется при успешном подтверждении и не может быть переигран.

Из-за `SetTextWithoutNotify` обновление скрытого поля не запускает `onValueChanged`. Поэтому кнопка вызывает `SendOnEndEdit` явно; отдельное поле с `onValueChanged → SetName` для этой задачи не подходит. Проверка Unity Builder должна загрузить prefab и bundle, сверить persistent listener, задать тестовый nonce, вызвать кнопку и убедиться, что `onEndEdit` получил именно его.

Старый Workshop bundle без этого listener безопасно не подтверждает обмен: обработчик игнорирует голый `TradeConfirm`. Новый prefab/bundle ещё требуется собрать в Unity, опубликовать поверх Workshop ID `3834982706` и проверить в игре. Регрессионные проверки модели покрывают устаревший nonce после изменения ревизии, закрытия UI, повторного открытия и новой сессии. Они не заменяют двухклиентский тест, проверку реального Unturned callback или crash/restore-приёмку. До завершения этих проверок Trade на основном сервере не включать.
