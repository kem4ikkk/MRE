# Изолированный шаг

`Prepare` только вычисляет полный план по подтверждённому снимку с полными списками и проверенными зонами. Никаких игровых API, планировщика, записи мира или хранения снимков здесь нет. Неизвестные данные, повтор ID и неверные остатки отклоняют весь план. Приоритеты берутся из `DecayModel`, геометрия из `PolygonZone`, выбор устройств из `ProtectionSearch`, целые HP и остатки из `FractionalHealth`. Граница устройства 50 м включена. Один вызов означает ровно один уже разрешённый цикл 300 секунд; часы этот код не проверяет.

`FakeGame` — только искусственный адаптер, принимающий последовательные шаги с проверкой номера ревизии и не допускающий повтор. Реальный сервер должен отдельно атомарно обеспечить подтверждение и актуальность полного снимка, хранение состояний и номера шага, идемпотентность, согласованность с сохранением мира, а также политику аварий и отката. Это не подтверждено этими тестами. Вводы тестового snapshot не следует менять параллельно вычислению. Повтор после рестарта этот адаптер не предотвращает без внешнего надёжного хранения.

`RuntimeGate` — проверяемая заготовка границы интеграции, а не подключение к серверу. Она требует подтверждений зон, ассетов, полного снимка, событий рейда, долговечного состояния, общей транзакции мира и состояния и восстановления; незавершённая транзакция запрещает запуск. Часы должны поступать от монотонного источника времени работающего процесса. При рестарте отсчёт начинается заново; задержка обработки не создаёт серию догоняющих шагов. Сбой часов, потеря подтверждения или неизвестный результат записи блокируют экземпляр. Логические флаги сами по себе не являются доказательством перечисленных свойств, а `Complete(true)` допустим только после фактически подтверждённой общей долговечной фиксации. Такой транзакции, журнала восстановления, реального адаптера и игровой проверки пока нет; включать механику нельзя.

`Building.PersistedMaxHealth` обязателен и должен поступать из сохранённого состояния вместе с остатками; несовпадение с текущим максимумом отклоняет весь план. Инициализация нового объекта и миграция максимума требуют отдельной подтверждённой политики.

`Adapter/ReadOnlyWorld.cs` собирает диагностические наблюдения наземных регионов через установленные игровые API только при явном разрешении вызова, без Rocket entry point и без записи в мир. Ошибка или неполный объект отменяют весь результат. Результат не является полным снимком для `StepEngine`: не подтверждены устойчивость ID, полнота регионов, состояние генераторов, состав сейфов, рейды и зоны. Адаптер собран против локальных DLL и проверен на отдельном временном сервере: пустой мир и fixture с одним полом, сейфом и генератором. Результаты и пределы проверки приведены в [DIAGNOSTIC.md](../Adapter/DIAGNOSTIC.md); интеграция и включение остаются запрещены до отдельной приёмки.

`DurableJournal` — изолированный прототип без подключения к игре, допускающий путь только во временной папке. Явный `Bootstrap` требует существующую пустую папку; `Load` не создаёт потерянное состояние. Отличить новую папку от потери всех данных можно только по внешним сведениям. Экземпляр удерживает файловую блокировку до `Dispose`, вызовы сериализованы, а конфликт блокирует экземпляр. Подтвердить intent может только экземпляр, успешно вызвавший `Begin`. После перезапуска pending и временный файл блокируют загрузку; автоматически подтверждать их нельзя. Блокировка проверена отдельным процессом для одного пути; псевдонимы пути, сетевые файловые системы и авария ОС не проверены.

`StateCodec` проверяет версию, цикл, активное время, идентификаторы объектов и ассетов, максимум HP, дробные остатки и оставшееся время рейда. Устойчивость игровых ID и достоверность входов не доказаны. SHA-256 выявляет случайное повреждение, но не подтверждает подлинность и свежесть старой корректной копии. Внешняя защита последовательности, инструмент сверки, устойчивость к авариям и согласование с сохранением Unity остаются неподтверждёнными. Журнал и мир не образуют общую транзакцию; применять прототип в рабочем мире нельзя.
