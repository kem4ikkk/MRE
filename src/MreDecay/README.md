# MRE Decay: текущее состояние

Движок расчёта и отдельный Rocket runtime shell собраны. Runtime shell по умолчанию выключен. Его production adapter пока намеренно возвращает неподтверждённые readiness gates, отказывается собирать snapshot и отказывается применять план. Не устанавливать и не включать этот shell на основном сервере: живая механика гниения ещё не подключена.

## Что уже проверено

- Изолированный периодический fixture в отдельном TEMP сервере PEI дождался 300 секунд и применил проверенные игровые API изменения к полу, сейфу и генератору. Свежий снимок подтвердил все три результата; FARM и SPIKE остались без изменений и были исключены. Зоны, raid и persisted state в этом fixture были синтетическими.
- `dotnet run --project tests/MreDecayEngine/MreDecayEngine.csproj --configuration Release` проверяет 225 случаев, включая отказ при каждом неподтверждённом gate, default-off, снятие готовности перед транзакцией, повторный вход и запрет повтора после неопределённого commit.
- `src/MreDecay/Adapter/Build-Runtime.ps1` собирает shell против локальных Rocket/Unturned DLL. Скрипт разрешает output только внутри `%TEMP%`; сборка не устанавливает DLL.

## Что блокирует реальные записи

Пока нет production adapters, которые могут достоверно подтвердить:

- проверенную геометрию зон PEI и актуальную загрузку её версии;
- корректные игровые asset/GUID сейфов MRE и полный allowlist размещённых объектов;
- полный снимок построек, включая проверки vehicle regions и границ всех загруженных регионов;
- постоянную идентичность объектов между перезапусками;
- регистрацию PvP-урона и 10-минутную блокировку ремонта;
- надёжное сохранение дробных остатков и номера цикла;
- атомарное совместное изменение HP мира и состояния плагина, проверку сохранения и восстановление после сбоя.

Любой отсутствующий или неизвестный gate блокирует pipeline до чтения мира и любых записей. Значения gate нельзя выставлять через конфигурацию. Сейчас в конфигурации доступен только `Enabled`, по умолчанию `false`; даже при ручном `Enabled=true` runtime остановится на readiness gate.

До включения нужны проверенные adapters для каждого пункта выше, безопасная транзакция всех результатов плана, тесты реальных API на изолированной копии, сценарии перезапуска/восстановления и отдельная приёмка. Наличие собранной DLL не означает, что runtime готов или включён.
