# Подтверждение обмена с проверкой версии

Игровое событие `onEffectButtonClicked` передаёт серверу игрока и имя кнопки; идентификатор окна и версия предложения в событии отсутствуют. Поэтому один постоянный `TradeConfirm` не позволяет отличить задержанный клик от нового. Ожидание, повторное открытие окна или простое обнуление подтверждений не решают проблему.

Текущая реализация использует отметку просмотра без кода: успешный `/trade list` записывает игроку текущую ревизию. Кнопка `TradeConfirm` и `/trade confirm` подтверждают только если записанная ревизия совпадает с текущей; в противном случае сервер просит снова выполнить `/trade list`. Любое изменение предложения увеличивает ревизию и сбрасывает отметки просмотра и подтверждения обеих сторон. UI redraw сам по себе отметку не ставит.

Это снижает риск случайного подтверждения задержанным кликом, но не даёт строгой гарантии: callback `onEffectButtonClicked` передаёт только повторно используемое статическое имя `TradeConfirm`, без ID окна, ревизии или времени нажатия. Если старый callback придёт уже после того, как игрок заново выполнил `/trade list` для новой ревизии, сервер не сможет отличить его от нового клика и он может подтвердить эту ревизию. Для строгой привязки потребовалось бы клиентское событие с токеном/ревизией либо иной callback с таким payload.

Модельный тест проверяет обязательность просмотра, сброс отметок просмотра обеих сторон после изменения, повторное подтверждение и отказ для постороннего SteamID. Игровые задержанные RPC и два клиента ещё не проверены; описанное выше окно гонки остаётся ограничением протокола. Аварийная сохранность инвентарей остаётся отдельным блокером; включать обмен для ценных предметов нельзя.
