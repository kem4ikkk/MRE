## Замечания и ограничения

1. **Расположение y260 не гарантирует отсутствие наложения при любом разрешении/UI scale.** PlayerLifeUI размещает шесть штатных полос по30 единиц, bottom10; statusIconsContainer находится над ними и занимает50 единиц с10 единицами зазора. При vanilla scale1 верх полос примерно190px от низа, статусных иконок250px. y160 пересекал оба; y260 при1080p даёт10px зазор до статусов. Custom CanvasScaler использует sqrt((width/1920)*(height/1080)): при1280x720 bottom173.3px, при1280x1024 bottom206.7px. Если штатный UI остаётся scale1, наложение возвращается. Это геометрическая модель, а не выполненный игровой тест. Настройки игрового UI могут менять штатный масштаб независимо. Нужны проверки реального клиента либо единый масштаб/расчёт отступа.
2. **ShowVirus пока включён в ReplacedFlags.** При HideNativeHud=true шкала иммунитета исчезнет, а custom больше не показывает её. До подтверждённого отключения механики это скрывает значимую информацию. Сейчас runtime HideNativeHud=false, поэтому риск не активирован.
3. **AssetsVerified не подтверждает доставку bundle каждому клиенту.** Серверный EffectAsset и успешная отправка SendUIEffect не являются клиентским ACK отрисовки. HideNativeHud=true может оставить клиента без обеих групп показателей. Сохранять false до гарантированной доставки/проверенного клиентского контракта.
4. RestoreNative восстанавливает только флаги, которые MRE застал включёнными и сам выключил: начально выключенные сохраняются. Но другой плагин, который позже выключит тот же флаг, будет переопределён restore; другой плагин, включающий его, будет переопределяться HideNative на каждом tick. API не даёт ownership. Нужен договор об одном владельце этих флагов.
5. Смерть скрывает HudContent и вызывает RestoreNative; возрождение показывает и вновь скрывает native в очередном tick. Disable/AssetsVerified=false/пропажа серверного asset вызывают Restore и очищают views. Ошибка Render вызывает Restore, затем Failed останавливает повторные попытки до пересоздания view. Reconnect с новым Player пересоздаёт view. Отключённый игрок удаляется без сетевого restore (новый Player получает дефолтную маску). Это подтверждено анализом исходников, не игровой проверкой.
6. Unload вызывает punchObserver.Dispose до восстановления views; текущий Dispose сам ловит исключение Harmony.Unpatch, отдельного blocker здесь не обнаружено. При исключении самого RestoreNative обход флагов прекращается, но Restore ловит ошибку и продолжает очистку custom UI; полного восстановления в сетевом отказе обещать нельзя.

Следующий шаг зависит от выбранного режима: сохранение native требует проверки общего масштабирования/отступа на720p и изменённом UI scale; замена native требует гарантированной доставки bundle всем игрокам и решения механики иммунитета. Игровые death/revive/reconnect, submerged, bleeding, gun HUD, unload/error сценарии остаются непроверенными.
