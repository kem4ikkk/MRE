# Модерация MRE

MreModeration 0.1.0 — самостоятельный серверный плагин LDM/Rocket. Он хранит профили и журнал, рассчитывает TrustScore, обрабатывает текстовые наказания и предоставляет серверное API для игровой панели. Полёт и инструменты администратора описаны в [INTERFACE.md](INTERFACE.md) и [FLIGHT.md](FLIGHT.md), снимки инвентаря — в [INVENTORY_AUDIT.md](INVENTORY_AUDIT.md). Визуальную часть делает отдельная сессия.

## Команды

`/staff help` показывает доступные действия. Для действий с причиной используйте SteamID64 из `/staff list` или `/admin players`:

| Пример | Действие | Право в дополнение к `mre.staff` |
|---|---|---|
| `/staff list [поиск]` | Список и поиск профилей | `mre.staff.list` |
| `/staff profile <SteamID64>` | Профиль, имена, доверие и время игры | `mre.staff.profile` |
| `/staff history <SteamID64> [тип]` | История действий | `mre.staff.history` |
| `/staff logs <SteamID64> [chat|command]` | Сохранённый журнал сообщений или команд | `mre.staff.logs` |
| `/staff note <SteamID64> <причина>` | Заметка | `mre.staff.note` |
| `/staff commend <SteamID64> <причина>` | Благодарность | `mre.staff.commend` |
| `/staff warn <SteamID64> <причина>` | Предупреждение | `mre.staff.warn` |
| `/staff kick <SteamID64> <причина>` | Исключить подключённого игрока | `mre.staff.kick` |
| `/staff ban <SteamID64> <срок> <причина>` | Установить бан | `mre.staff.ban` |
| `/staff mute <SteamID64> <срок> <причина>` | Запретить отправку сообщений в текстовый чат | `mre.staff.mute` |
| `/staff unban <SteamID64> <причина>` | Отменить действующие баны этого модуля | `mre.staff.unban` |
| `/staff unmute <SteamID64> <причина>` | Снять действующие mute этого модуля | `mre.staff.unmute` |
| `/staff revoke <SteamID64> <id записи> <причина>` | Отменить отдельную запись; для ban/mute дополнительно требуется право снятия | `mre.staff.revoke` |

Срок: `30m`, `2h`, `7d`, секунды с суффиксом `s`, либо `perm`; временный срок ограничен 365 днями. Команда `/mytrustscore` показывает игроку собственную оценку; право `mre.trustscore` добавлено группе обычного игрока. Mute ограничивает текстовый чат: блокировка голосовой связи не реализована.

Права проверяются для каждого вызова на сервере, в том числе для вызовов через UI. Только подключённый actor может выполнять административные действия. Native администратор также проходит проверку; донатные группы не получают административных разрешений. Самому себе нельзя выдать kick, ban или mute. Изменения с записью в журнал получают идентификатор операции; API отклоняет повтор с тем же идентификатором и другим содержимым.

## Профили и TrustScore

Профиль создаётся при подключении, фиксирует известные имена, первый и последний зафиксированный вход и наработанное время. Он не восстанавливает историю до установки плагина. Основной файл — приватный `Rocket/Plugins/MreModeration/profiles/<SteamID64>.json`; файлы автоматически входят в полную резервную копию экземпляра и не отправляются в Git.

Начальная формула MRE, заданная локальной XML-конфигурацией: 50 баллов, +2 за каждый полный час игры с пределом +25, +5 за благодарность, −10 за предупреждение, −15 за выполненный kick. Результат ограничен 0–100. Отменённые записи не учитываются. Это проектное решение MRE: формула оригинального BTModeration не подтверждена видео.

Журнал хранит до 50 имён, 1000 записей модерации и 200 сообщений/команд на профиль. При заполнении лимита записей действия останавливаются до обслуживания; новые записи не заменяют историю молча. Если профиль повреждён, он не пересоздаётся пустым. Изменение trust-групп по умолчанию выключено; при включении плагин принимает только специально названные пустые `mre_trust_*` группы, без административных и донатных полномочий. Логи чата и команд включены в текущих настройках; аргументы неизвестных команд скрываются.

## Сроки наказаний и восстановление

Для ban журнал сначала получает состояние `pending`, затем вызываются native `SteamBlacklist.ban` и сохранение, после чего запись становится `active`. Проверка MRE ограничивает вход при активной или неопределённой записи, а срок автоматически истекает в UTC. Native-бан с чужой причиной не заменяется и не снимается этой командой. При ошибке между записью и native-операцией нужна сверка владельцем; не повторяйте выдачу вслепую.

Mute и его срок сохраняются между рестартами. При недоступном или повреждённом журнале проверка бана закрывает вход до сверки, проверка чата отклоняет сообщение. Автоматическое истечение регулярно отмечается в истории. Проверки срока, отмены и рестарта выполнены на изолированной логике; реальные подключения и наказания игровых аккаунтов ещё нужно проверить на тестовых игроках.

## Интеграции

Webhook выключен по умолчанию, локальный URL не задан. При настройке разрешается только HTTPS Discord webhook; очередь сохраняется на диске, ошибки повторяются с задержкой. Сетевая доставка работает по принципу «как минимум один раз»: при потере подтверждения получателя повтор может создать дубликат. Никакой реальный webhook не подключён и не испытывался. Не публикуйте URL и файлы с конфигурацией в Git.

Необязательный бот просмотра профилей и история его тестов описаны в [README бота](../scripts/moderation-bot/README.md). Бот не запущен и не связан с Discord; нужны токен, гильдия и разрешённые роли владельца.

## Сборка, установка и проверка

```powershell
.\scripts\Build-MreModeration.ps1
dotnet run --project src/MreModeration/Tests/MreModeration.Tests.csproj --configuration Release
```

Сборка сохраняется в `runtime/builds/MreModeration`; она не устанавливается на работающий сервер. Для обновления собрать также MreInterface, MreInventoryAudit и MreFlight; выполнить Save/Stop, полную копию, `Apply-MreSettings.ps1 -Apply`, затем `Install-MreFeatures.ps1 -AdminOnly -Apply`, запуск и проверку журнала. `-AdminOnly` не меняет MreEssentials, TPA, HOME и HUD. Полный режим установщика дополнительно требует отдельные сборки MreEssentials, MreKits и Teleportation. После установки 31.10.2026 плагин зарегистрировал `/staff` и `/mytrustscore`; Unity-сценарии с реальными игроками, внешним webhook и Discord ещё не принимались.

Для следующего ревью отдельно проверить: пересечение ban с внешним blacklist, таймеры в офлайне и после рестарта, повторные вызовы UI с тем же operationId, отказ записи, права обычного/донатного/модераторского аккаунтов, объём файлов и влияние синхронной записи на игровой поток. Нагрузочного теста на 24 игрока пока нет.
