# Инвентарь и снимки смерти MRE

MreInventoryAudit — собственный MIT-плагин для LDM/Rocket. Работает вместе с MreInterface и MreModeration. Графический просмотр подключает отдельная UI-сессия.

## Команды

| Команда | Назначение | Право |
|---|---|---|
| `/inspectinventory <игрок>` | Снимок текущих личных вещей и надетой одежды | `mre.inventory.inspect` |
| `/previewdeath <игрок> [номер]` | Список сохраненных смертей или содержимое одной | `mre.inventory.deaths` |
| `/restoredeath <SteamID64> <номер>` | Подготовить компенсацию и получить токен | `mre.inventory.restore` |
| `/restoredeath confirm <токен>` | Подтвердить выбранную компенсацию за 30 секунд | `mre.inventory.restore` |

Каждый вызов требует реально подключенного администратора и текущих прав: native admin либо `mre.admin` вместе с правом действия. API повторяет эти проверки на главном игровом потоке. Обычные игроки и донатные группы доступа не получают. Имена должны совпадать полностью и однозначно; для офлайн-истории используется SteamID64. В чате выводятся первые 30 вещей; API возвращает весь ограниченный снимок.

## Что сохраняется

Событие `PlayerLife.OnPreDeath` вызывается до нативного выпадения вещей. Плагин сохраняет оружейные и личные страницы до `PlayerInventory.STORAGE`, надетую одежду, ID, количество, качество и копию `state`. Открытый чужой контейнер и временная область подбора не включаются.

Файлы `Rocket/Plugins/MreInventoryAudit/deaths/<SteamID64>.json` приватные, входят в копию всего экземпляра и не публикуются. Хранятся последние 20 снимков на игрока; неопределенные `pending` не удаляются автоматически. При повреждении файла его нельзя подменять пустым журналом: доступ к этим снимкам прекращается до сверки. Автоматического удаления старых каталогов игроков нет; их объем контролируется при обслуживании.

## Компенсация

Это новая административная выдача вещей из снимка. Она сохраняет содержимое текущего инвентаря и не забирает лут с места смерти; администратор должен учитывать это при решении о компенсации. Одежда выдается предметами в свободные места, экипируется игроком вручную. Раскладка вещей по прежним координатам не восстанавливается. Цель должна быть подключена и жива, а свободного места должно хватать на весь снимок. Отсутствующий после удаления мода asset блокирует выдачу.

Подтверждение привязано к администратору, обеим текущим игровым сессиям, ID снимка и сроку. Номер в списке используется только при подготовке; последующая новая смерть не меняет выбранный ID. Токен одноразовый. Перед предметами на диск записывается `pending`, после полной выдачи — `completed`. Повтор завершенного снимка блокируется и после перезапуска. Неполная выдача откатывает только новые экземпляры по ссылке; прежние похожие предметы не удаляются и вещи не выбрасываются на землю.

Журнал JSON и игровой save не образуют общую транзакционную БД. После аварии результат компенсации может требовать ручной сверки. Не снимать `pending` автоматически: вещи могли сохраниться. Перед исправлением: Save, корректная остановка, копия всего экземпляра, сверка инвентаря и журнала. Состояния `completed` тоже нельзя повторять после восстановления более раннего игрового save без проверки.

## API для UI

`MreInventoryAuditPlugin.Instance` может быть `null` до загрузки/после выгрузки. Методы вызываются на игровом потоке:

- `Inspect(actor, targetId)` — `InventoryView` текущих вещей; доступ только для чтения.
- `GetDeaths(actor, targetId)` — до 20 `InventoryView`, новые первыми.
- `PrepareRestore(actor, targetId, deathNumber)` — `RestorePreview` с токеном и сроком.
- `ConfirmRestore(actor, token)` — повторная проверка и русское сообщение результата.
- События `DeathCaptured(playerId, snapshotId)` и `InventoryRestored(actorId, playerId, snapshotId)` — после сохранения соответствующего состояния.

`InventoryView`: PlayerId, SnapshotId, AtUtc, RestoreStatus, Items. Элемент: Id, Name, Amount, Quality, Page, X, Y, Rotation, WornSlot. Бинарный `state` в UI не передается. Имена экранировать при отображении rich text. UI получает actor только из настоящего серверного события кнопки.

## Проверки

`scripts/Build-MreInventoryAudit.ps1` собирает DLL и manifest в `runtime/builds/MreInventoryAudit`, не устанавливая их. `dotnet run --project src/MreInventoryAudit/Tests/MreInventoryAudit.Tests.csproj --configuration Release` проверяет сохранность состояния, UTC, перезапуск, повторную выдачу, полный инвентарь, откат, неопределенный результат и поврежденный журнал.

Сборка и проверки журнала не доказывают работу инвентаря в Unity. До публичной приемки отдельно проверяются смерть с одеждой и оружием, просмотр из обычного аккаунта, заполненный инвентарь, отключение цели, повтор подтверждения, рестарт с `pending` и реальные сетевые обновления вещей. Ни одна постройка или вещь реального игрока ради теста не удаляется.
