# MreVault — тестовая реализация `/s`

`/s` открывает личное хранилище 4×4 через штатное окно Unturned. При русской раскладке сообщение `.ы` также открывает хранилище, выполняя те же проверки прав и ограничений; сообщение не публикуется в чате. Применять только на тестовом сервере и с тестовыми предметами. Производственное хранение ценных предметов и продажи расширений не включать до полной приёмки.

01.11.2026 владелец подтвердил работу `.ы` в локальной игре. Проверка аварийного сохранения и согласованного восстановления остаётся незавершённой.

Команде нужно право `mre.vault`. Шаблон прав содержит его для группы default, но уже установленный `RocketPermissions.xml` сам не меняется: после резервного копирования добавьте право точечно в действующий файл. Сообщения используют общую иконку MRE и доступны без изображения, если клиент не может загрузить URL.

Команда проверяет доступность Teleportation и ограничений боя/рейда; при отсутствии guard или активном запрете открытие отклоняется. Для открытой сессии Harmony перехватывает перемещение и обмен, а выбрасывание непосредственно из VAULT запрещает. Закрытие и guard проверяются во время работы; другие способы изменения предметов и область действия raid block не подтверждены. Ограничения Teleportation не равны полной защите атакующих, защищающихся и offline-баз.

Данные: `Servers/MRE/Rocket/Plugins/MreVault/storage/<SteamID>.vault`, `.initialized` и `.pending`. Перед открытием создаётся pending; при штатном закрытии сохраняются состояние инвентаря и VAULT, затем pending удаляется. Маркер `.initialized` после первой успешной записи позволяет обнаружить пропажу `.vault`, пока сам маркер сохранён; потерю обоих файлов или старые данные без маркера он обнаружить не может. Сохранение игры и файла VAULT не являются единой транзакцией: в аварии возможны потеря или дублирование, включая промежуток после удаления pending. При ошибке оставшийся pending блокирует повтор, но содержит только текстовый маркер, без снимка инвентаря. Сохраняйте файлы и логи, сверяйте с согласованной резервной копией, не удаляйте pending и не выдавайте вещи повторно без ручного решения. Нельзя смешивать резервные копии мира и VAULT из разных моментов.

## Сборка и установка на Windows

Установите .NET SDK и PowerShell; используйте проект в отдельном тестовом каталоге с установленными U3DS/LDM и Harmony. Сначала соберите Teleportation.MRE с теми же игровыми DLL, затем MreVault:

```powershell
.\src\Teleportation.MRE\Build.ps1
.\scripts\Build-MreVault.ps1
.\scripts\Install-MreFeatures.ps1 -VaultOnly
```

Последняя команда без `-Apply` проверяет подготовленную сборку. После остановки сервера и резервного копирования установку тестовой DLL можно выполнить ` .\scripts\Install-MreFeatures.ps1 -VaultOnly -Apply `. Убедитесь, что лицензия, Teleportation и Harmony доступны серверу, а права в установленном XML актуальны. Если U3DS установлен в другом каталоге, используйте `-GameDirectory` у сценария сборки; целевой сервер установки задаётся структурой проекта `runtime/server`. Не использовать библиотечные reference DLL вместо DLL работающего сервера.

Изолированные тесты: `dotnet run --project src/MreVault/Tests/MreVault.Tests.csproj`. Они не подтверждают работу игрового API. Полный список ручных проверок всех изменений сессии — `docs/VAULT_TEST_PLAN.md`; результаты фиксируются отдельно и не предполагаются успешными.
