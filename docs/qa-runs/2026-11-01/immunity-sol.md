## Практические ограничения

- Инвариант100 имеет окно до1сек при первом сканировании/сторонней прямой записи в virus. Префикс askInfect лишь пропускает уменьшение, сам низкое значение не повышает. Это соответствует документации; абсолютное «всегда100 с первого кадра входа» не доказано.
- Клиентская радиация предсказывается между синхронизациями. В радиации на24 игроков при2сек получается до12 периодических SendVirus/сек совокупно, плюс первоначальная отправка, revive и scan-коррекции. Тест частоты не является нагрузочным тестом реального сервера.
- При ошибке отправки gate уже расходует текущий интервал; повторная попытка возможна после2сек. Если askDisinfect успел записать _virus=100, но затем сеть бросила исключение, Update не повторит её из-за100; radiation prefix повторит в следующий доступный интервал. Вне радиации клиентская видимость после сетевой ошибки не гарантирована.
- Runtime изменение Enabled/Verified не опрашивается после успешного Load. Документация корректно требует перезапуск/выгрузку для отключения.
- Отсутствие Harmony может остановить загрузку класса до собственного Load/catch; механика останется штатной, но конкретный текст ошибки даст Rocket. Нельзя обещать собственное сообщение при всех отказах зависимостей.
- Событие OnTellVirus_Global от askDisinfect запускает слушателей других плагинов. Прямая сторонняя модификация состояния и конфликтующие Harmony prefixes не покрываются гарантией совместимости.
- Повышение100 меняет сохраняемое состояние игроков; Unload не возвращает прежнее значение. Откат механики — снять плагин/перезапустить, откат состояния — соответствующая резервная копия с оценкой потерянного прогресса. docs/IMMUNITY.md это явно описывает.

Остаётся игровая приёмка в отдельной копии: реальное применение Harmony, вход/возрождение, заражённые consumables/атаки, radiation с/без защиты, сохранение и restart, клиентская шкала и сетевые ошибки. Прямой урон deadzone этим решением не отключается. Рабочий сервер трогать до окончания текущей игры нельзя.
