# Независимая проверка плагинов MRE

Дата: 30.10.2026. Проверялись исходники и изолированные тесты, без изменения установленной DLL или сохранений работающего сервера.

## Результат

- MreEssentials: **42 изолированные проверки прошли**. Покрыты снимок участников, округление кворума, повторные/поздние/офлайн-голоса, срок голосования, список локальных команд, повтор GUID, старые запросы при запуске, путь относительно EXE при смене рабочего каталога, отказ выхода из `runtime/control` и чтение диагностических полей.
- Teleportation MRE: исходные **12 проверок прошли**, после исправления обнаруженных ошибок — **20 проверок прошли**. Тесты используют фактический код запросов TPA, правил владельца/группы и детектора движения с подменой Unity/Steam.
- Teleportation MRE **1.8.3.2** собран по установленным U3DS DLL в `runtime/review-builds/Teleportation/plugin/`. Независимая сборка не заменяла установленный серверный плагин.

Команды обычного повторного запуска тестов:

```powershell
dotnet run --project src/MreEssentials/checks/VoteSessionChecks.csproj --configuration Release
dotnet run --project src/Teleportation.MRE/Tests/Teleportation.MRE.Tests.csproj --configuration Release
```

## Исправленные ошибки

1. В обработчиках урона баррикадам и строениям сравнение `group == playerGroup` ошибочно считало двух одиночек одной группой при обоих значениях `0`. Поэтому чужая соло-база могла обходить raid block. Такое же сравнение принимало постороннего онлайнового одиночку за представителя владельца соло-базы. Общая функция `RaidOwnershipRules.IsOwnerOrGroupMember` теперь учитывает совпадение групп только при ненулевом идентификаторе группы; владелец по SteamID определяется отдельно.
2. Детектор движения удалял исчезнувшего игрока, но в той же итерации обращался к его `transform`. Добавлен `continue`; отдельные проверки подтвердили пропуск исчезнувшего игрока и сохранение отмены TPA при реальном движении.

Обновлены версия сборки, [описание форка](../src/Teleportation.MRE/README.md) и `mre_patch.assembly_version` в `plugins.lock.json`. Исходные контрольные суммы архивов Restore Monarchy не изменялись.

## Границы вывода

Проверки не доказывают работу с двумя реальными клиентами. Кровати, реальный урон, Harmony, перемещение, голосование в текущем игровом Mono и сетевое подключение должны подтверждаться отдельным протоколом координатора.

В исходниках MreEssentials проверены ограничения запуска голосования: ночь при `NightOnly`, минимум два игрока, порог 60%, длительность 60 секунд и пауза 300 секунд. Изолированный harness проверяет чистые классы и диагностику; он не исполняет весь Unity-цикл `MreEssentialsPlugin`. Кворум не уменьшается при выходе игроков; голоса отключенных игроков не учитываются. Пауза голосований и cooldown TPA не сохраняются через перезагрузку плагина/сервера.

Рейдовая логика Teleportation по-прежнему относится к атакующему и базе с онлайновым владельцем или членом его реальной группы. Глобального радиуса блокировки, самостоятельного ограничения защитников и проверки всех VAULT/торговых путей этот форк не реализует.

Локальный controlbridge не открывает сетевой порт и не принимает произвольные команды. Его безопасность зависит также от ограниченных NTFS-прав каталога `runtime/control/MRE`, которые устанавливает настройка проекта. Подключение GameStores, платежи, снятие платных групп и VAULT в этой проверке не выполнялись.
