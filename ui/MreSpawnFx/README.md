# MRE Spawn FX

Оригинальный процедурный эффект: 18 коротких зелёных частиц вокруг позиции персонажа, без сторонних текстур и клиентского кода. Генератор использует стандартный shader Unity `Particles/Standard Unlit`. Каждый импульс живёт 0,5 с и обновляется сервером каждые 0,4 с; эффект остаётся в точке создания, а не прикреплён к телу. При движении возможен заметный след. После смерти, атаки, отключения, истечения или выгрузки новые импульсы прекращаются, последний исчезает максимум через 0,5 с плюс сеть. Общий clear по ID не используется, чтобы не стереть эффекты других игроков.

Unity 2022.3.62f3: открыть проект и выполнить `MreSpawnFxBuilder.BuildWindows` в batchmode или меню MRE. Результат: `runtime/ui-builds/MreSpawnFx/Windows/MreSpawnFx/`, пара `.dat` и `.unity3d`. ID 29065 и GUID 7744a548037a48a6a2ec469b54e7c2e1 должны совпасть с плагином и не конфликтовать с другими модами. Пакет необходимо доставить на сервер и всем клиентам через согласованную Workshop-зависимость; только серверной DLL недостаточно. Владелец должен обновить и опубликовать выбранный пакет и настроить зависимость; эта сборка ничего не публикует и не устанавливает. Windows bundle, другие платформы не проверены.

Сервер рассылает импульс клиентам в радиусе 64 м, без адресации одному защищённому игроку. Эффект не является индикатором безопасности: потери пакетов, настройки графики и задержка могут скрыть его. Визуал и материал требуют проверки двумя клиентами, в движении и после завершения защиты.

Старая сборка непригодна: её журнал содержит сообщения об исключении `ParticleSystem` и `ParticleSystemRenderer`. После добавления `com.unity.modules.particlesystem` сборка 08.11.2026 завершилась успешно: журнал `runtime/ui-builds/MreSpawnFx-20261108.log` содержит prefab и не содержит этих сообщений. На момент проверки серверный Workshop bundle и результат сборки совпадали по SHA-256 `e1d3a7300ed36ab74e5b5ecd46a8b3cd2eb390e26e3c6897716f36d8f60198d5`; сервер зарегистрировал GUID и ID. Это не подтверждает загрузку prefab и отображение на клиенте. Проверка двумя клиентами остаётся необходимой; следует проверить, что качество эффектов в настройках клиента не выключено, и сравнить клиентский Workshop bundle с серверным. В SDK игра пропускает обычные эффекты при `effectQuality == OFF`.

Контракт: [EffectAsset SDG](https://github.com/SmartlyDressedGames/U3-SDK/blob/main/Assets/Runtime/Assembly-CSharp/Unturned/Bundles/EffectAsset.cs), [EffectManager SDG](https://github.com/SmartlyDressedGames/U3-SDK/blob/main/Assets/Runtime/Assembly-CSharp/Unturned/Managers/EffectManager.cs), проверено 07.11.2026. `relevantPlayerID` отправляет одному клиенту; его отсутствие включает рассылку по расстоянию. `Lifetime_Spread 0` исключает стандартный разброс времени жизни.
