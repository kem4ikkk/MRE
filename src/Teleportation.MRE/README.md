# Teleportation MRE 1.8.3.2

Небольшой проверяемый MIT-форк [Teleportation 1.8.3](https://github.com/RestoreMonarchyPlugins/Teleportation/tree/9c046b50ab7fc0a456263134d7d6f07b2461fbb9). Исходная лицензия Restore Monarchy сохранена в [LICENSE](LICENSE). Авторство исходного плагина сохраняется; изменения MRE не являются официальным релизом Restore Monarchy.

## Изменение поведения

- И отправитель, и получатель проходят combat/raid проверки при создании запроса, принятии и непосредственно перед переносом.
- Принятый запрос остается в списке во время ожидания. Повторное `/tpa accept` не ставит второй перенос в очередь, а второй исходящий запрос не создает параллельный перенос даже при сброшенном внешнем cooldown.
- `/tpa cancel`, `/tpa deny` и отключение любого участника отменяют уже принятое ожидающее перемещение.
- Подключение под тем же SteamID после отключения не возрождает старый запрос: проверяются текущие игровые объекты обеих сторон.
- Истекший непринятый запрос очищается перед новым. Неудачный финальный перенос не обнуляет антиспам cooldown.
- Исправлена проверка пещеры: высота земли берется в позиции игрока, а не в `Vector3.zero`.
- При выгрузке плагина ожидающие переносы отменяются.
- Нулевой идентификатор группы не объединяет всех одиночек: чужая соло-база не считается своей, а посторонний одиночка в онлайне не считается владельцем офлайн-базы.
- Проверка движения безопасно пропускает уже исчезнувшего игрока и продолжает проверять остальных.

Объем исправления ограничен TPA. Исходное определение рейда, радиус, блокировки защитников и ограничения сторонних VAULT/магазинов здесь не переписаны. См. [границы сборки](../../config/plugins/README.md).

## Сборка

```powershell
.\src\Teleportation.MRE\Build.ps1
```

Используется установленный .NET SDK/Roslyn и Mono/Unity/LDM DLL из `runtime/server` только как ссылки для компиляции. Устанавливать .NET Framework targeting pack или скачивать случайный redist не требуется. Для проверки по другой собственной установленной игре можно указать `-ReferenceRoot 'D:\Steam\steamapps\common\Unturned'`; основная поставка собирается по установленному U3DS.

Результат и manifest записываются в `runtime/plugin-builds/Teleportation.MRE/`, бинарные файлы не коммитятся. Плагин сохраняет имя сборки `Teleportation` для интеграции с MoreHomes; версия сборки — `1.8.3.2`. Для независимой сборки без изменения установочных артефактов можно указать `-OutputDirectory` внутри `runtime`, например `runtime/review-builds/Teleportation/plugin`.

## Выполненные проверки

30.10.2026 повторены и расширены проверки: **20 поведенческих сценариев прошли** на фактических `TPARequest.cs`, `TeleportationRequestHelper.cs`, `RaidOwnershipRules.cs` и `MovementDetectorComponent.cs`. Первые 12 покрывают sender/recipient combat, recipient raid до принятия и во время ожидания, повторный accept и параллельный запрос, отмену/отклонение во время ожидания, disconnect/reconnect, устаревший объект игрока, смерть получателя и замену истекшего запроса. Добавлены шесть сценариев владельца/нулевой и ненулевой группы и два сценария исчезновения/движения игрока.

```powershell
dotnet run --project src/Teleportation.MRE/Tests/Teleportation.MRE.Tests.csproj --configuration Release
```

Harness подменяет Unity/Steam и управляет очередью времени, поэтому он проверяет ветвления и жизненный цикл реального кода запроса. Это не замена испытаниям с двумя подключенными клиентами, реальным уроном, кроватями и текущим Mono. Поведение террейна и Harmony MoreHomes в этом harness не проверяется. Серверная загрузка и игровые сценарии отмечаются отдельно по фактическому журналу координатором.
