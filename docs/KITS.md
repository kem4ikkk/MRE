# Наборы MRE

MreKits 0.1.0 предоставляет `/kits` и `/kit <имя>`. Обе команды и публичные методы серверного API проверяют `mre.kit`; это право выдается обычным игрокам отдельно от администрирования. Графический UI разрабатывает другая сессия.

Первый запуск создает `Rocket/Plugins/MreKits/MreKits.configuration.xml`. Выбранный владельцем набор `start` доступен раз в 3600 секунд: кленовый лук (`353`), пять отдельных стрел (`348`), зелёная парка (`162`), ковбойские джинсы (`208`), спальник (`294`), два бинта (`95`), топор (`16`), две банки фасоли (`13`) и две бутылки воды (`14`). Парка вмещает 6×3, джинсы 5×3 — столько же, сколько полицейские рубашка и штаны соответственно; размеры самих предметов и значение брони также совпадают. Значения и ID сверены с файлами установленного U3DS. Лук может быть уже заряжен еще одной стрелой. Состав и интервал настраиваются в XML; шаблон находится в `config/plugins/MreKits/MreKits.configuration.xml`. Предметы создаются через `EItemOrigin.ADMIN` с качеством 100. Существующий XML сам не заменяется при обновлении DLL.

## Учет и предотвращение повторной выдачи

Перед выдачей весь набор размещается в копиях личных страниц инвентаря. Оружейные слоты, открытый чужой контейнер и временная область предметов не используются. Если набор не помещается целиком, инвентарь и cooldown не изменяются. Затем в `claims.json` атомарно записывается `pending` с UTC-временем; файл сбрасывается на диск до обращения к инвентарю.

Выдача выполняется в одном игровом потоке по заранее выбранным координатам без выбрасывания на землю. Если включено `AutoEquipClothing`, свободные слоты футболки и брюк заполняются автоматически; уже надетую одежду не заменяем. При отказе или исключении до попытки надевания удаляются только предметы с точными ссылками на созданные объекты. После попытки надевания безопасный откат не подтвержден: `pending` остается и запрещает повтор до ручной сверки. После успешной выдачи запись становится `completed` и сохраняет время следующего получения.

Для сохранения старых ограничений `start` использует запись журнала `starter`; прежние `pending` и `NextClaimUtc` продолжают действовать. Оба имени одновременно в XML запрещены. Доступ к выдаче также закрывается при бое, рейде или недоступности Teleportation; пределы raid block описаны отдельно в документации Teleportation.

`claims.json.previous` — предыдущая версия журнала. Резервное копирование сервера должно включать каталог плагина. Журнал содержит SteamID и не должен попадать в Git или публичные отчеты. Пустой/поврежденный JSON запрещает загрузку плагина: журнал нельзя автоматически удалять или заменять пустым.

Игровой мир и JSON не образуют единую транзакционную базу. Авария после сохранения резервирования может оставить игрока без предметов с заблокированным набором. Это намеренный отказ от автоматического повтора при неопределенном результате. Для сверки: сохранить и остановить сервер, сделать резервную копию, проверить инвентарь/сохранение и серверный журнал, затем вручную убрать конкретную подтвержденно невыданную запись `SteamID:имя` либо перевести выданную запись в `completed`, сохранив `NextClaimUtc`. После этого запустить сервер. Не снимать `pending` вслепую: предметы могли сохраниться.

## Сборка и проверки

```powershell
.\scripts\Build-MreKits.ps1
dotnet run --project src/MreKits/Tests/MreKits.Tests.csproj --configuration Release
```

Результат — `runtime/builds/MreKits/MreKits.dll` и `build-manifest.json` с SHA-256 плагина и ссылочных сборок. Скрипт не устанавливает и не перезапускает сервер. Нужны локальный U3DS, LDM/Rocket и его `Newtonsoft.Json.dll`. Код MRE доступен в репозитории; SDK DLL в Git не включаются.

Проверки журнала и транзакции: успешное сохранение, перезапуск, повтор до cooldown, точная UTC-граница, отдельные игроки/наборы, полный инвентарь без изменений, резервирование до выдачи, аварийный `pending`, откат после отказа/исключения, неподтвержденный откат, ошибка записи до инвентаря, поврежденный журнал и защита от внешнего изменения DTO. Эти проверки не запускают Unity. Фактическая укладка вещей, отображение в клиенте и взаимодействие со сторонними inventory-плагинами проверяются отдельно в игре.

Игровая приемка: обычный игрок выполняет `/kits`, `/kit start`, получает указанный набор; повтор блокируется, после переподключения/перезапуска cooldown сохраняется; заполненный инвентарь получает отказ без частичной выдачи, старые похожие вещи сохраняются. Проверяются оба варианта: пустые и занятые слоты одежды. Статус этих игровых сценариев до ручного прохождения — **ожидает проверки**.

## Контракт для UI

`MreKits.MreKitsPlugin.Instance.GetKitNames(UnturnedPlayer)` возвращает доступные имена. `GetClaim(player, name)` возвращает копию `ClaimRecord` (`Status`, `ClaimedUtc`, `NextClaimUtc`) либо `null`. `Claim(player, name)` повторно проверяет доступ/жизнь/cooldown и возвращает русское сообщение результата. `KitClaimed(ulong steamId, string name)` вызывается после сохраненной успешной выдачи. Методы вызываются только с главного потока Unturned. Подписчик события не может откатить уже завершенную выдачу своим исключением. Не изменять и не выдавать предметы из UI самостоятельно.

TPA проверен отдельно по текущим исходникам другой сессии: версия 1.8.3.3, 37 сценариев, delay 5 секунд, движение разрешено, Б принимает / Ю отклоняет, штатные Plugin Keys учитывают переназначение. Эта сессия не меняет их настройки и не реализует визуальную часть.
