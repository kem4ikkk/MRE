# Окно обмена MRE (UI-only)

Окно использует только текст: собственное предложение показано сеткой из десяти ячеек, предложение партнёра — списком из десяти строк. Нажатие собственной ячейки открывает общий редактор предложения, а не отдельную ячейку инвентаря. Эксперимент с иконками удалён из текущего интерфейса.

Отдельный Unity **2022.3.62f3** проект. Генератор создаёт uGUI окно: две стороны по десять предметов, сведения о партнёре, состояние подтверждений, кнопки подтверждения/отмены. Свои ячейки кликабельны, чужие — только текст. Показываются серверные названия, количество и качество. Выбор вещей выполняется отдельным серверным адаптером в нативном инвентаре; этот bundle сам не перемещает имущество. В чате остаются только `/trade <ник>`, `/trade accept` и `/trade deny`; после принятия запроса всё остальное выполняется в UI.

В проекте нет игрового клиентского кода, EventSystem или закрытых ресурсов REDLINE. Шрифт — встроенный `LegacyRuntime.ttf`. В bundle стандартные Canvas, CanvasScaler, CanvasGroup, GraphicRaycaster, Image, Text, Button. Имена Button автоматически обрабатываются нативным `EffectManager.hookButtonsInUIEffect` Unturned. Canvas имеет sortingOrder=20, окно 1100×750 при reference resolution 1920×1080; сервер должен скрывать или очищать его при открытии нативного инвентаря, смерти, потере доступа и окончании сессии. Доставка и клики требуют проверки реальным клиентом.

## Контракт сервера

Effect ID **48622**, key **14822**, GUID **a986933995df4d29816efcc37f87b220**, адрес prefab **Effect**. Эти значения отличаются от существующего MreHud. Источник контракта — [effect-manifest.json](effect-manifest.json).

Текстовые поля: `TradePartner`, `TradeOwnOffer`, `TradePartnerOffer`, `TradeStatus`, `TradeOwn0`…`TradeOwn9`, `TradeOther0`…`TradeOther9`. Скрытое поле ввода: `TradeConfirmToken`. Кнопки: `TradeConfirm`, `TradeCancel`, `TradeOwnSlot0`…`TradeOwnSlot9`. Корень видимости — `TradeContent`. Тексты не поддерживают rich text; длинные строки ограничиваются размером ячейки. Серверу следует выводить короткое имя, количество и качество; остальные сведения — отдельным описанием. `TradeOwnSlotN` открывает выбор в нативном инвентаре. Кнопка `TradeConfirm` вызывает `InputField.SendOnEndEdit` у скрытого поля, и Unturned передаёт текущий nonce через `onEffectTextCommitted`; голый callback с именем `TradeConfirm` ничего не подтверждает. `TradeCancel` обрабатывается сервером для текущей сессии. Изменение любого предложения сбрасывает оба подтверждения и меняет nonce.

После `/trade accept` сервер открывает окно обоим игрокам. Каждая сторона получает случайный одноразовый nonce, привязанный к текущей сессии, ревизии предложения и поколению UI. Нажатие кнопки отправляет nonce, находившийся в скрытом поле в момент клика. После изменения предложения, закрытия или повторного открытия окна и новой сессии предыдущий nonce отклоняется. Unity Editor-проверка должна подтвердить сохранённый persistent listener и прохождение тестового текста из `Button.onClick` в `InputField.onEndEdit`. Эти проверки исходника ещё не доказывают игровой callback: новая версия bundle должна быть собрана и проверена двумя клиентами. Сервер продолжает проверять текущего игрока, состояние обеих сторон, сроки и combat/raid guard.

## Сборка на Windows

Открыть `ui/MreTrade` в установленном и активированном Unity 2022.3.62f3. Меню **MRE → Trade → Создать окно обмена** создаёт `Assets/MreTrade/Effect.prefab`; меню **Собрать Windows bundle** генерирует и проверяет свежий bundle. Либо:

```powershell
.\scripts\Build-MreTradeAssets.ps1 -UnityEditorPath 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe'
```

Результат: `runtime/ui-builds/MreTrade/Windows/MreTrade/{MreTrade.dat,MreTrade.unity3d}` и `bundle-build.json`. Скрипт проверяет версию Unity/платформу, свежесть результата, UnityFS, SHA-256 и идентификаторы. Editor повторно загружает bundle и проверяет адрес Effect, имена полей, 12 кнопок, скрытое поле nonce, его persistent listener и передачу тестового значения через `onEndEdit`, а также raycast/rich-text настройки. При ошибке Editor старый bundle не считается успешной сборкой. Без Unity executable сборка завершается понятным отказом; `.unity3d` не фабрикуется.

## Доставка и приёмка

Bundle нужен серверу и обоим клиентам. Steam-клиент сообщил об успешной загрузке отдельного Workshop-пакета **MRE Trade**, ID `3834982706`, 07.11.2026 02:31:18 (MSK). 08.11.2026 в 00:45 (MSK) SteamCMD анонимно скачал пакет; состав payload и SHA-256 `MreTrade.dat`/`MreTrade.unity3d` совпали с опубликованным receipt. Это подтверждает доступность скачивания по ID, но не фактическую установку отдельным игровым клиентом и не работу UI в игре. Данные загрузки и хеши сохранены в `runtime/workshop-packages/MreTrade-1ca1bf08cfbb40408381bb067d64773a/package.json`; этот runtime-пакет не входит в git. Существующий HUD, его файлы, ID и конфигурация не заменяются. Не устанавливать trade bundle в общий клиентский `Bundles` как встроенный core-ресурс: существующий MreHud уже выявил конфликт `invalid asset guid` при переходе на другие серверы. `Exclude_From_Master_Bundle` обязателен для legacy .dat; `Master_Bundle_Override` запрещён проверкой сборки. Фактическую структуру Workshop нужно подтвердить клиентским входом, без ручной глобальной копии.

Проверить двумя клиентами: вход и автоматическую доставку, разрешение кнопок только своей сессии, различимые предложения, отмену/изменение подтверждений, длинные имена, 1280×720/1920×1080/широкий экран, открытие и закрытие нативного инвентаря, отсутствие перекрытия штатных меню/курсора после закрытия, отключение партнёра, бой/рейд и невозможность поздним кликом подтвердить новую сессию. Asset build и браузерный preview не доказывают сохранность предметов или аварийный recovery.

Проверка исходного контракта без Unity: `python tests/CheckMreTradeUi.py`. Runtime-пакет проверяется командой `python tests/CheckMreTradeWorkshopPackage.py <путь-к-пакету>`; downloaded payload — дополнительным `--downloaded-payload <путь-к-папке-3834982706>`. Валидатор сверяет состав файлов и SHA-256 с receipt. Готовый опубликованный пакет есть только в runtime-папке, указанной выше. Предпросмотр: [ui/trade-preview/index.html](../trade-preview/index.html). Дополнительный браузерный тест: `node tests/CheckMreTradePreview.cjs` при установленных Playwright и Chromium; путь к системному браузеру можно задать через `CHROMIUM_EXECUTABLE`. Тест поднимает временный сервер только на 127.0.0.1, проверяет 20 ячеек, свои кнопки, подтверждение, отмену, повторный старт и отсутствие горизонтального переполнения на 1920×1080 и 1280×720, затем закрывает сервер. Unity executable в текущей среде недоступен, поэтому повторная сборка bundle из исходников не выполнена. Публикация и успешное анонимное скачивание не заменяют установку клиентом и проверку обмена в игре. Это отдельная браузерная иллюстрация, не снимок игрового окна и не готовый клиентский bundle.
