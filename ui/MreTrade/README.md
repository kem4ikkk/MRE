# Окно обмена MRE (UI-only)

Окно использует только текст: собственное предложение показано сеткой из десяти ячеек, предложение партнёра — списком из десяти строк. Нажатие собственной ячейки открывает общий редактор предложения, а не отдельную ячейку инвентаря. Эксперимент с иконками удалён из текущего интерфейса.

Отдельный Unity **2022.3.62f3** проект. Генератор создаёт uGUI окно: две стороны по десять предметов, сведения о партнёре, состояние подтверждений, кнопки подтверждения/отмены. Свои ячейки кликабельны, чужие — только текст. Показываются серверные названия, количество и качество. Выбор вещей выполняется отдельным серверным адаптером в нативном инвентаре; этот bundle сам не перемещает имущество. В чате остаются только `/trade <ник>`, `/trade accept` и `/trade deny`; после принятия запроса всё остальное выполняется в UI.

В проекте нет игрового клиентского кода, EventSystem или закрытых ресурсов REDLINE. Шрифт — встроенный `LegacyRuntime.ttf`. В bundle стандартные Canvas, CanvasScaler, CanvasGroup, GraphicRaycaster, Image, Text, Button. Имена Button автоматически обрабатываются нативным `EffectManager.hookButtonsInUIEffect` Unturned. Canvas имеет sortingOrder=20, окно 1100×750 при reference resolution 1920×1080; сервер должен скрывать или очищать его при открытии нативного инвентаря, смерти, потере доступа и окончании сессии. Доставка и клики требуют проверки реальным клиентом.

## Контракт сервера

Effect ID **48622**, key **14822**, GUID **a986933995df4d29816efcc37f87b220**, адрес prefab **Effect**. Эти значения отличаются от существующего MreHud. Источник контракта — [effect-manifest.json](effect-manifest.json).

Текстовые поля: `TradePartner`, `TradeOwnOffer`, `TradePartnerOffer`, `TradeStatus`, `TradeOwn0`…`TradeOwn9`, `TradeOther0`…`TradeOther9`. Кнопки: `TradeConfirm`, `TradeCancel`, `TradeOwnSlot0`…`TradeOwnSlot9`. Корень видимости — `TradeContent`. Тексты не поддерживают rich text; длинные строки ограничиваются размером ячейки. Серверу следует выводить короткое имя, количество и качество; остальные сведения — отдельным описанием. Нажатие `TradeOwnSlotN` открывает выбор в нативном инвентаре, а `TradeConfirm` и `TradeCancel` обрабатываются только сервером для текущей сессии. Изменение любого предложения сбрасывает оба подтверждения на сервере, не в prefab.

После `/trade accept` сервер открывает окно обоим игрокам. Кнопка «Подтвердить обмен» фиксирует показанную в UI текущую ревизию и подтверждает только её; после изменения предложения UI обновляется, и обе стороны должны проверить состав заново перед повторным нажатием. Callback кнопки не содержит ID окна, сессии или ревизии, поэтому задержанный callback после нового обновления либо после новой сессии с теми же игроками остаётся возможной гонкой, и строгая привязка не гарантируется. Сервер продолжает проверять текущего игрока, состояние обеих сторон, сроки и combat/raid guard. Проверка двух клиентов и доставки сообщений остаётся обязательной.

## Сборка на Windows

Открыть `ui/MreTrade` в установленном и активированном Unity 2022.3.62f3. Меню **MRE → Trade → Создать окно обмена** создаёт `Assets/MreTrade/Effect.prefab`; меню **Собрать Windows bundle** генерирует и проверяет свежий bundle. Либо:

```powershell
.\scripts\Build-MreTradeAssets.ps1 -UnityEditorPath 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe'
```

Результат: `runtime/ui-builds/MreTrade/Windows/MreTrade/{MreTrade.dat,MreTrade.unity3d}` и `bundle-build.json`. Скрипт проверяет версию Unity/платформу, свежесть результата, UnityFS, SHA-256 и идентификаторы. Editor повторно загружает bundle и проверяет адрес Effect, все имена полей, 12 кнопок, raycast/rich-text настройки. При ошибке Editor старый bundle не считается успешной сборкой. Без Unity executable сборка завершается понятным отказом; `.unity3d` не фабрикуется.

## Доставка и приёмка

Bundle нужен серверу и обоим клиентам. 7 ноября 2026 года его заново собрали Unity 2022.3.62f3 непосредственно из release-ветки `release/mre-trade-review`; результат соответствует текущему prefab и генератору, SHA-256 bundle: `29d4ccd4c449f69067fa0d8a598c287ad397ff08f0d9578128fa7ebe5e716444`. Локальный пакет сформирован скриптом `tools/trade-workshop/Build-MreTradeWorkshopPackage.ps1` и прошёл проверку состава, GUID, SHA-256, `.dat`, UnityFS и превью; скрипт печатает путь к свежей папке, фактический путь загрузки — её подкаталог `Content`, превью — `MreTrade-preview.jpg` в корне пакета. Публичная карточка ещё не создана, Workshop ID не назначен, доставка клиентам не проверена. Превью `workshop-preview.jpg` — оригинальная иллюстрация интерфейса, не снимок игры. Существующий HUD, его файлы, ID и конфигурация не заменяются. Не устанавливать trade bundle в общий клиентский `Bundles` как встроенный core-ресурс: существующий MreHud уже выявил конфликт `invalid asset guid` при переходе на другие серверы. `Exclude_From_Master_Bundle` обязателен для legacy .dat; `Master_Bundle_Override` запрещён проверкой сборки. Фактическую структуру Workshop подтвердить чистым клиентом, без ручной глобальной копии.

### Подготовленная карточка Workshop

- Название: `MRE Trade`.
- Описание: «UI-ресурс обмена для MRE. Для работы требуется серверный плагин MreTrade. Запрос: `/trade <ник>`; принятие или отказ: `/trade accept` или `/trade deny`. Выбор предметов и подтверждение выполняются в игровом окне. Интерфейс экспериментальный; доставка, игровые клики и сохранность предметов ещё проходят приёмку.»
- Категория: `Object` → `Effect`; раздел `Ready-to-Use`; видимость `Public`; список Allowed IPs пустой.
- Запусти `tools/trade-workshop/Build-MreTradeWorkshopPackage.ps1`; выбери `Content` из напечатанной папки пакета и отдельно укажи лежащий рядом `MreTrade-preview.jpg`. В `Content` нет `package.json`. Исходник обложки хранится в `ui/MreTrade/workshop-preview-source.png`.
- Превью — иллюстрация макета, а не скриншот. До публичного запуска сервера требуется двухклиентская игровая приёмка.

Проверить двумя клиентами: вход и автоматическую доставку, разрешение кнопок только своей сессии, различимые предложения, отмену/изменение подтверждений, длинные имена, 1280×720/1920×1080/широкий экран, открытие и закрытие нативного инвентаря, отсутствие перекрытия штатных меню/курсора после закрытия, отключение партнёра, бой/рейд и невозможность поздним кликом подтвердить новую сессию. Asset build и браузерный preview не доказывают сохранность предметов или аварийный recovery.

Проверка исходного контракта: `python tests/CheckMreTradeUi.py`. Предпросмотр: [ui/trade-preview/index.html](../trade-preview/index.html). Дополнительный браузерный тест: `node tests/CheckMreTradePreview.cjs` при установленных Playwright и Chromium; путь к системному браузеру можно задать через `CHROMIUM_EXECUTABLE`. Тест поднимает временный сервер только на 127.0.0.1, проверяет 20 ячеек, свои кнопки, подтверждение, отмену, повторный старт и отсутствие горизонтального переполнения на 1920×1080 и 1280×720, затем закрывает сервер. Браузерная иллюстрация не является снимком игры и не проверяет доставку Workshop или игровую обработку UI. Лицензия генератора и preview — MIT, см. [LICENSE](LICENSE).
