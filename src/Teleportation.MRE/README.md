# Teleportation MRE 1.8.3.3

Небольшой проверяемый MIT-форк [Teleportation 1.8.3](https://github.com/RestoreMonarchyPlugins/Teleportation/tree/9c046b50ab7fc0a456263134d7d6f07b2461fbb9). Исходная лицензия Restore Monarchy сохранена в [LICENSE](LICENSE). Авторство исходного плагина сохраняется; изменения MRE не являются официальным релизом Restore Monarchy.

## Изменение поведения

- И отправитель, и получатель проходят combat/raid проверки при создании запроса, принятии и непосредственно перед переносом.
- Принятый запрос остается в списке во время ожидания. Повторное `/tpa accept` не ставит второй перенос в очередь, а второй исходящий запрос не создает параллельный перенос даже при сброшенном внешнем cooldown.
- `/tpa cancel`, `/tpa deny` и отключение любого участника отменяют уже принятое ожидающее перемещение.
- Подключение под тем же SteamID после отключения не возрождает старый запрос: проверяются текущие игровые объекты обеих сторон.
- Истекший непринятый запрос очищается перед новым. Неудачный финальный перенос не обнуляет антиспам cooldown.
- Исправлена проверка пещеры: высота земли берется в позиции игрока, а не в `Vector3.zero`.
- При выгрузке плагина ожидающие переносы отменяются.
- Нулевой идентификатор группы не объединяет всех одиночек: чужая соло-база не считается своей, а посторонний одиночка в онлайне не считается владельцем офлайн-базы.
- Проверка движения безопасно пропускает уже исчезнувшего игрока и продолжает проверять остальных.
- В MRE TPA ожидает **5 секунд** после согласия (`TPADelay=5`, `CancelOnMove=false` в конфигурации MRE). Оба игрока могут двигаться; отправитель переносится к текущей позиции получателя. Combat/raid, смерть и отключение по-прежнему запрещают перенос.
- Базовый cooldown TPA — **100 секунд**. Короткие команды `/tpa a` и `/tpa d` равнозначны `/tpa accept` и `/tpa deny`; они показаны в русской справке `/tpa`.
- Стандартные Plugin Key 1 и 2 принимают и отклоняют входящий запрос; на стандартном клиенте это физические клавиши **Б/Ю** (`,`/`.`). При переназначении в настройках Unturned используется новая привязка игрока. Удержание клавиши не повторяет действие. Во время отсчёта Ю отменяет перенос у любого из участников.
- HUD и клавиши используют один и тот же `GetUiRequest`: сначала принятый перенос, затем первый входящий запрос, затем исходящий. На одного участника нельзя запустить два переноса одновременно; следующие входящие запросы ожидают своей очереди.
- `RequestStateChanged(CSteamID)` уведомляет обе стороны о создании, принятии и очистке запроса. `ExecuteAtUtc`, `DelaySeconds` и `RemainingSeconds` отдают общему MreHud тот же пятисекундный отсчёт, который использует очередь переноса. Оставшееся время вычисляется монотонными часами; отдельная задача телепортации для UI не создается.
- Смерть немедленно очищает запросы, а завершение, отмена и исключение API телепортации убирают отсчёт. При выгрузке очищаются клавиши и подписчики UI.

В этой сборке также находится отслеживаемый `HomeTeleportRequest` для собственного [MoreHomes MRE](../MoreHomes.MRE/README.md): пять секунд, свободное движение, Ю для отмены, единая карточка и запрет параллельных HOME/TPA. Модель проверяет актуальный объект игрока, смерть и combat/raid до и перед переносом; MoreHomes проверяет выбранную зарегистрированную кровать и выполняет безопасный перенос. Выгрузка любого владельца, отмена и ошибка API очищают HOME.

Исходное определение рейда, радиус, блокировки защитников и ограничения сторонних VAULT/магазинов здесь не переписаны. См. [границы сборки](../../config/plugins/README.md).

## Сборка

```powershell
.\src\Teleportation.MRE\Build.ps1
```

Используется установленный .NET SDK/Roslyn и Mono/Unity/LDM DLL из `runtime/server` только как ссылки для компиляции. Устанавливать .NET Framework targeting pack или скачивать случайный redist не требуется. Для проверки по другой собственной установленной игре можно указать `-ReferenceRoot 'D:\Steam\steamapps\common\Unturned'`; основная поставка собирается по установленному U3DS.

Результат и manifest записываются в `runtime/plugin-builds/Teleportation.MRE/`, бинарные файлы не коммитятся. Плагин сохраняет имя сборки `Teleportation` для интеграции с MoreHomes; версия сборки — `1.8.3.3`. Для независимой сборки без изменения установочных артефактов можно указать `-OutputDirectory` внутри `runtime`, например `runtime/review-builds/Teleportation/plugin`.

## Подключение HUD

Общий визуальный интерфейс находится в отдельном `src/MreHud`, исходник uGUI effect — в `ui/MreHud`. Этот форк предоставляет состояние и горячие клавиши без обязательной зависимости от UI bundle: `/tpa accept`, `/tpa deny` и `/tpa cancel` продолжают работать, если визуальный мод еще не собран или не доставлен клиенту. Установка DLL сама по себе не создает графический интерфейс.

Актуальные стандартные клавиши и токены `<plugin_0/>`, `<plugin_1/>` проверены 30.10.2026 по [официальному ControlsSettings.cs](https://github.com/SmartlyDressedGames/U3-SDK/blob/main/Assets/Runtime/Assembly-CSharp/Unturned/Settings/ControlsSettings.cs). Сборка по установленным локальным U3DS/Mono/LDM DLL выполнена; визуальная приемка двумя клиентами отмечается отдельно в [UI_VERIFICATION.md](../../docs/UI_VERIFICATION.md).

## Выполненные проверки

30.10.2026 повторены и расширены проверки: **37 поведенческих сценариев прошли**. Harness компилирует фактические `TPARequest.cs`, `TeleportationRequestHelper.cs`, `TeleportationConfiguration.cs`, `PluginKeyEdges.cs`, `RaidOwnershipRules.cs` и `MovementDetectorComponent.cs`.

Проверены настоящие значения `LoadDefaults()` (задержка 5 секунд, движение разрешено, Plugin Keys 0/1), постановка переноса в очередь с delay `5`, отсчёт без второй задачи, смена позиции обоих участников и актуальная позиция цели при переносе, приоритет и FIFO запросов, отмена именно показанной карточки, Ю у обеих сторон во время отсчёта, удержание клавиш, защита от параллельных переносов и очистка при исключении API. Сохранены проверки combat/raid обеих сторон, cancel/deny, disconnect/reconnect, устаревшего объекта игрока, смерти, истечения запроса, владельца и нулевой/ненулевой группы, безопасной проверки движения исчезнувшего игрока.

```powershell
dotnet run --project src/Teleportation.MRE/Tests/Teleportation.MRE.Tests.csproj --configuration Release
```

Harness подменяет Unity/Steam/Rocket dispatcher и игровые объекты, поэтому он проверяет ветвления и жизненный цикл реального кода запроса. Захват delay подтверждает переданный интервал `5`, но не измеряет пять секунд настоящего Unity/Rocket-времени. Реальная обработка ввода и разрешений на подключённом клиенте, доставка и отображение UI, террейн, кровати и Harmony MoreHomes здесь не проверяются. Игровая приёмка двумя клиентами пока не выполнена; её пункты и границы проверок записаны в [UI_VERIFICATION.md](../../docs/UI_VERIFICATION.md).
