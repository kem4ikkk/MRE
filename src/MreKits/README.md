# MreKits: стартовый набор

Исходный код подготовлен для LDM/Rocket. `/kits` показывает состав, `/kit start` выдаёт набор живому игроку с правом `mre.kit` не чаще раза в час. В наборе кленовый лук (353), пять отдельных кленовых стрел (348), белая футболка (180), рабочие джинсы (2), два бинта (95), походный топор (16), две банки фасоли (13) и две бутылки воды (14). Лук по стандартным данным может уже содержать стрелу. Одежда надевается, если соответствующий слот свободен.

Выдача планируется заранее с учетом места от новых футболки и брюк. Если соответствующий слот одежды пуст, плагин надевает вещь из набора; иначе сохраняет имеющуюся одежду игрока и кладёт новую в инвентарь. При нехватке места выдача не начинается. При недоступной проверке или блокировке боя/рейда Teleportation выдача закрыта. Эта проверка наследует ограничения существующей модели Teleportation и не является общей защитой зоны рейда.

Каждый SteamID имеет журнал в `Servers/MRE/Rocket/Plugins/MreKits/claims`: перед выдачей создаётся `.pending`, после успешной выдачи — `.done`. При прерывании процесса оставшийся `.pending` блокирует автоматический повтор; администратор вручную сверяет журнал, инвентарь, логи и сохранение до любых действий. Состояние инвентаря и журнала не является общей транзакцией. Каталог claims необходимо включать в согласованные резервные копии и учитывать при политике вайпа. Смена системного времени влияет на таймер.

Для сборки сначала выполнить `src/Teleportation.MRE/Build.ps1`, затем `scripts/Build-MreKits.ps1` на машине с U3DS и .NET SDK. Скрипт собирает DLL, но не устанавливает её. Установка и испытания — после остановки сервера и резервной копии. Локально сборка и игровые тесты не проводились: нужны фактические DLL и клиенты. Проверить свободное и занятое место, все ID и комплектацию лука, бой/рейд, повтор через час, рестарт, восстановление копии и прерывание во время выдачи. Изображение чата размещено в этой ветке; после переноса в main необходимо обновить URL и проверить его доступность клиентам.
