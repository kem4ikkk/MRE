# Проверка UI обмена

Статус: тестовая реализация, по умолчанию выключена (`UiEnabled=false`, `AssetsVerified=false`). Unity bundle, доставка клиентам и игровой прогон не проверены. Использовать отдельную копию сервера и тестовые вещи. Существующий текстовый обмен и прежний HUD не заменять без резервной копии.

1. Собрать серверную DLL по DLL фактического U3DS согласно `src/MreTrade/README.md`. Собрать UI в Unity 2022.3.62f3 по `ui/MreTrade/README.md`. Проверить GUID/key и отсутствие конфликтов с другими эффектами.
2. Подготовить отдельный Workshop-пакет, проверить получение asset сервером и двумя чистыми клиентами. Не ставить asset в глобальный клиентский Bundles. Только после проверки доставки и резервной копии включать тестовые флаги на тестовом экземпляре.
3. Два разных клиента: запрос и принятие /trade; нажать каждую свою клетку, открыть нативное хранилище, выбрать вещи, закрыть его. Убедиться, что обе стороны видят актуальные название, количество и качество, иконки вещей в основном окне пока не реализованы. Чужое предложение редактировать нельзя.
4. Проверить изменение предложения после одного/двух подтверждений, повторные и устаревшие нажатия, отмену, выход, перезаход, смерть, combat/raid, другой контейнер и выгрузку плагина. Ни копию, ни чужой предмет нельзя получить, использовать как инструмент, надеть, выбросить, разобрать, перенести, уничтожить или использовать для крафта до завершения обмена. Проверять все семь слотов одежды и различные типы предметов.
5. На копии проверить заполненный инвентарь, предметы с одинаковыми ID и разным состоянием/качеством, патроны и модификации, отсутствие дубля/потери при подтверждении, а также влияние сторонних плагинов. Сверять исходные предметы, предложения, инвентари и землю до/после.
6. Смоделировать обрыв/ошибку на открытии/закрытии контейнера и прервать процесс на разных этапах commit. При неопределённости сохранить журнал, мир и логи; не выдавать вещи повторно до ручной сверки. Сохранение инвентарей не атомарно, а raid guard покрывает не все сценарии. Полный порядок см. в `docs/TRADE_TEST_PLAN.md`.

Не включать на публичном сервере до успешной двухклиентской проверки, аудита RPC установленных DLL и аварийного восстановления. Записывать PASS/FAIL/BLOCKED с версией игры и доказательствами.
