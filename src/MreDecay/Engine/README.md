# Изолированный шаг

`Prepare` только вычисляет полный план по подтверждённому снимку с полными списками и проверенными зонами. Никаких игровых API, планировщика, записи мира или хранения снимков здесь нет. Неизвестные данные, повтор ID и неверные остатки отклоняют весь план. Приоритеты берутся из `DecayModel`, геометрия из `PolygonZone`, выбор устройств из `ProtectionSearch`, целые HP и остатки из `FractionalHealth`. Граница устройства 50 м включена. Один вызов означает ровно один уже разрешённый цикл 300 секунд; часы этот код не проверяет.

`FakeGame` — только искусственный адаптер, принимающий последовательные шаги с проверкой номера ревизии и не допускающий повтор. Реальный сервер должен отдельно атомарно обеспечить подтверждение и актуальность полного снимка, хранение состояний и номера шага, идемпотентность, согласованность с сохранением мира, а также политику аварий и отката. Это не подтверждено этими тестами. Вводы тестового snapshot не следует менять параллельно вычислению. Повтор после рестарта этот адаптер не предотвращает без внешнего надёжного хранения.

`RuntimeGate` — проверяемая заготовка границы интеграции, а не подключение к серверу. Она требует подтверждений зон, ассетов, полного снимка, событий рейда, долговечного состояния, общей транзакции мира и состояния и восстановления; незавершённая транзакция запрещает запуск. Часы должны поступать от монотонного источника времени работающего процесса. При рестарте отсчёт начинается заново; задержка обработки не создаёт серию догоняющих шагов. Сбой часов, потеря подтверждения или неизвестный результат записи блокируют экземпляр. Логические флаги сами по себе не являются доказательством перечисленных свойств, а `Complete(true)` допустим только после фактически подтверждённой общей долговечной фиксации. Такой транзакции, журнала восстановления, реального адаптера и игровой проверки пока нет; включать механику нельзя.

`Building.PersistedMaxHealth` обязателен и должен поступать из сохранённого состояния вместе с остатками; несовпадение с текущим максимумом отклоняет весь план. Инициализация нового объекта и миграция максимума требуют отдельной подтверждённой политики.

`Adapter/ReadOnlyWorld.cs` собирает диагностические наблюдения наземных и транспортных регионов через установленные игровые API только при явном разрешении вызова, без Rocket entry point и без записи в мир. Ошибка или неполный объект отменяют весь результат. Результат не является полным снимком для `StepEngine`: не подтверждены устойчивость ID, attach/reload жизненный цикл транспорта, состояние генераторов, состав сейфов, рейды и зоны. Ранее выполненные пустой-мир и object fixtures запускались до vehicle-расширения и подтверждают только тогдашний ground path. Текущая версия скомпилирована против локальных DLL, но её vehicle path ещё не запускался на сервере. Результаты и пределы проверки приведены в [DIAGNOSTIC.md](../Adapter/DIAGNOSTIC.md); интеграция и включение остаются запрещены до отдельной приёмки.

`DurableJournal` — изолированный прототип без подключения к игре, допускающий путь только во временной папке. Явный `Bootstrap` требует существующую пустую папку; `Load` не создаёт потерянное состояние. Отличить новую папку от потери всех данных можно только по внешним сведениям. Экземпляр удерживает файловую блокировку до `Dispose`, вызовы сериализованы, а конфликт блокирует экземпляр. Подтвердить intent может только экземпляр, успешно вызвавший `Begin`. После перезапуска pending и временный файл блокируют загрузку; автоматически подтверждать их нельзя. Блокировка проверена отдельным процессом для одного пути; псевдонимы пути, сетевые файловые системы и авария ОС не проверены.

`StateCodec` проверяет версию, цикл, активное время, идентификаторы объектов и ассетов, максимум HP, дробные остатки и оставшееся время рейда. Устойчивость игровых ID и достоверность входов не доказаны. SHA-256 выявляет случайное повреждение, но не подтверждает подлинность и свежесть старой корректной копии. Внешняя защита последовательности, инструмент сверки, устойчивость к авариям и согласование с сохранением Unity остаются неподтверждёнными. Журнал и мир не образуют общую транзакцию; применять прототип в рабочем мире нельзя.

`RuntimeZoneQuery.TryGetAcceleratedZone` возвращает false для скрытия HUD при неработающем gate, неподтверждённых данных, во время незавершённого шага и после ошибки координат. Это чистая граница с синтетическими подтверждениями в тестах: вызывающая реализация обязана подтвердить зоны и все остальные условия, вызывать её на игровом потоке и отзывать подтверждение при потере готовности. DRAFT не загружается и не является подтверждением; подключённого игрового runtime пока нет.

## Проект протокола запуска и checkpoint — не реализован

Сначала сервер выключен, а оператор имеет проверенную копию мира, состояния и независимого якоря последнего подтверждённого поколения. Новый мир разрешается инициализировать только по отдельному подтверждению его происхождения; отсутствие файлов состояния не означает новый мир. На запуске сверяются версия сервера и карты, hash проверенного набора зон, идентификаторы и целостность мира и состояния, номер поколения и его якорь вне восстанавливаемого набора. Ошибка, отсутствие любого свидетельства, pending или несовпадение блокируют и гниение, и ремонт. Корректная старая пара мира и состояния без актуального внешнего якоря не доказывает свежесть; восстановление старой пары требует явной согласованной процедуры и нового якоря, а не автоматического bootstrap.

Перед циклом нужно зафиксировать намерение с поколением, идентичностью и ожидаемым fingerprint сохранённого мира и состояния, дождаться надёжной записи, выполнить изменения и сохранить мир, затем проверить фактически записанный checkpoint и надёжно зафиксировать совместное поколение вместе с состоянием и независимым якорем. При аварии между любыми этапами, неизвестном результате, повторном доставлении или несовпадении fingerprint автоматически не повторять и не подтверждать цикл: запуск остаётся заблокирован до отдельной сверки и восстановления. Это требование к будущей транзакции, не утверждение, что Unity save и `DurableJournal` сейчас атомарны или что fingerprint игрового мира уже определён. До реализации и испытаний аварий/restore `WorldStateTransactionVerified` и `RecoveryVerified` должны оставаться false.

`ReviewedZoneLoader` — отдельный парсер, не подключённый к игровому runtime. Он принимает только статус `VERIFIED`, все контуры каждой локации, геометрически корректные полигоны и совпадающие SHA-256 переданных байтов `Level.hierarchy` и `Chart.png`; также требует независимо переданный ожидаемый SHA-256 всего проверенного документа. Контрольная сумма фиксирует содержимое, но не доказывает, что кто-либо проверил границы в игре; надёжное происхождение ожидаемого хеша должен обеспечить будущий процесс приёмки. DRAFT отклоняется даже при совпадении всех переданных хешей. Проверены синтетические две области Holman с промежутком и отказ на фактическом черновике PEI. До отдельной игровой проверки статус зон не подтверждён.
Уточнение: `LoadPei` принимает только карту PEI и точные хеши установленной версии `Level.hierarchy`/`Chart.png`, а также сверяет ID и названия со всеми 21 видимыми локациями, извлечёнными из этой версии карты. Ограничения: до 256 вершин в контуре, до 256 контуров и 4096 вершин суммарно. Карта с другой версией потребует повторной сверки списка и кода; никакой VERIFIED-файл сейчас не создан. Хеш cartography отдельно не требуется для уже проверенных мировых координат при закреплённых исходниках и хеше документа; преобразование из изображения и правильность координат должны быть проверены при приёмке.

`CheckpointVerifier` реализует только отдельное сравнение поколения и SHA-256 двух переданных снимков с независимым якорем: отсутствующие данные, старое поколение, незавершённая транзакция и изменённые данные отклоняются. Синтетические проверки прошли, но код не устанавливает происхождение/свежесть якоря, полноту snapshot и атомарность игровой записи. Он не подключён к серверу и не меняет статус готовности; до доказательства этих свойств протокол остаётся проектом.

`CheckpointCoordinator` задаёт порядок через `ICheckpointBackend`: проверка текущего поколения, долговременное намерение, изменение мира, сохранение с проверкой, публикация состояния и независимого якоря, повторная проверка. Каждый отказ или исключение необратимо блокирует экземпляр; автоматического повтора нет. Проверки с искусственным backend покрывают все стадии, но реальный backend отсутствует. Поэтому сами имена методов не являются доказательством долговечности, атомарности, реального save либо независимости якоря, и координатор не разрешает запись в игровой мир.

`IsolatedWorldFingerprint` отдельно вычисляет в TEMP хеш имён, размеров и содержимого `Barricades.dat`/`Structures.dat`, отвергает отсутствующие/пустые файлы и reparse points; он предназначен только для остановленного и заблокированного от записи сервера. Эти два файла не являются доказанным полным снимком мира, одновременно не блокируются, а проверка путей имеет файловые гонки; полнота и quiescence должны подтверждаться извне. `IsolatedPendingStore` открывает существующий `DurableJournal` только при совпадении поколения и состояния, записывает намерение до операции и после прерывания отказывает в открытии pending. Оба компонента изолированы и не связаны с Unity save или независимым якорем. Тесты с временными файлами не являются аварийной проверкой реального процесса или файловой системы; реальный backend checkpoint и crash recovery отсутствуют.

`IsolatedCheckpointBackend` соединяет координатор, pending и отпечаток двух файлов для файловой репетиции под TEMP. У него нет реализованной публикации независимого якоря: последний этап всегда отказывает, намерение остаётся pending, новый запуск заблокирован. В тестах делегаты имитируют изменение/сохранение файла и отказ на трёх стадиях; это проверка поведения при возврате ошибки, а не принудительное завершение процесса, настоящий `SaveManager.save()` или полноценное восстановление. К игровому runtime этот backend не подключён.

Репетиционный backend теперь блокирует повтор стадий, обращение из другого потока, вложенный вызов и использование после `Dispose`; ошибка внутри callback сохраняет pending и блокирует последующие стадии. Тесты вложенного `Save` из `Apply` и `Apply` из `Save` подтверждают отказ внешнего вызова без повторной операции. Этап `SaveAndVerifyWorld` лишь вызывает переданный тестовый делегат и проверяет читаемость двух файлов, а не доказывает ожидаемую версию мира или сохранение Unity; публикация якоря не реализована и всегда отказывает.

Процессные crashpoints: `dotnet run --project tests/MreDecayEngine/MreDecayEngine.csproj -c Release` создаёт отдельную временную копию искусственных `Barricades.dat`/`Structures.dat` и journal, запускает отдельный процесс и вызывает его принудительное завершение после записи pending, после изменения `Structures.dat` и после `Flush(true)` файла. Родитель проверяет ожидаемые байты `2/3/3` и отказ повторного открытия pending после освобождения process lock. PASS 175 на текущем окружении. Это реальные завершения процесса между файловыми операциями, но не сбой ОС/питания, не игровой save, не восстановление и не подтверждение долговечности каталогов; временные каталоги тест автоматически удаляет. Публикация независимого якоря в backend отсутствует.

## Состояние Rocket runtime shell

`Adapter/DecayRuntimePlugin.cs` собран только как кандидат на runtime. Конфигурация имеет один переключатель `Enabled` со значением по умолчанию `false`; зонные, raid, snapshot, persistent identity, vehicle coverage и durable transaction gates не читаются из конфигурации. Production `UnavailableRuntimeAdapter` пока возвращает все readiness gates выключенными, не наблюдает мир и отказывается применять план. Включение переключателя остановится на readiness gate до чтения мира и любых записей.

`Adapter/Build-Runtime.ps1` — только compile-only сборка: output разрешён исключительно в `%TEMP%`; скрипт не устанавливает DLL. Rocket `Update()` использован как Unity server-thread scheduler с 300-секундным monotonic timer. `DecayRuntimePipeline` проверяет readiness до observation, повторно проверяет её перед единственным вызовом будущего транзакционного адаптера, проверяет allowlist и полный набор результатов, запрещает re-entry и ставит coordinator на паузу после неопределённого commit. Реальной атомарной транзакции пока нет. Engine suite: 216 PASS на текущем наборе; отдельные Probe и Rocket сборки: 0 ошибок и 0 предупреждений.

Изолированный periodic fixture подтвердил 300-секундный расчёт и checked API изменения трёх объектов на временном сервере. Он использовал mock зон, raid и persisted state, поэтому этот результат не доказывает production adapters или live decay. Shell не подключён к сборке/установке основного сервера, не является production runtime и не должен там устанавливаться.
