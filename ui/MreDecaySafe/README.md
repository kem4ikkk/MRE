# Эскиз металлического сейфа MRE

Изолированный исходник строит собственную статичную 3D-модель из примитивов Unity: корпус, дверца, ручка, замок и петли. Unity 2022.3.62f3: открыть этот каталог как проект, выполнить `MRE → Generate safe visual prototype`. Результаты `Assets/Generated/MRE_Safe_Visual_100.prefab`, `MRE_Safe_Visual_200.prefab`, `MRE_Safe_Visual_300.prefab` — одинаковые визуальные эскизы, без коллайдера и интерактивности. Генератор перезаписывает свои материалы и prefab в папке Generated.

Игровой объект не подготовлен: пользователь выбрал 100, 200 и 300 клеток; ID/GUID и рецепт не утверждены. Не создан контракт storage prefab и размещения, не подтверждены игровая геометрия, физика, анимация, сохранение, доставка и загрузка клиентом. Штатный серверный Locker.dat показывает поля Type Storage, Useable Barricade, Build Storage, Storage_X/Y и Locked, но копирование его идентификаторов или данных не делает этот эскиз совместимым. Требуется отдельно проверить контракт актуального U3 SDK, собрать собственный bundle, разрешить идентификаторы и провести игровые испытания. Workshop не опубликован, рабочий runtime не изменён.

Возможные сетки 10×10, 10×20 и 15×20 математически дают нужное число клеток, но их работоспособность не подтверждена. Официальный [Storage Assets](https://docs.smartlydressedgames.com/en/stable/items/storage-asset.html) определяет `Storage_X/Y` как byte и число колонок/строк, не гарантируя число отдельных предметов. Исторический [вопрос SDG SDK](https://github.com/SmartlyDressedGames/U3-SDK/issues/3468) сообщает лимит 255 записей в 2022 году; это не доказательство текущего лимита. Не обещать 300 предметов 1×1 без проверки текущего кода и испытания.

Официальные контракты данных: [Storage Assets](https://docs.smartlydressedgames.com/en/latest/items/storage-asset.html) и [Barricade Assets](https://docs.smartlydressedgames.com/en/latest/items/barricade-asset.html). В `contracts/storage.dat.template` сохранены подтверждённые типы без ID/GUID; шаблон не является рабочим .dat. До проверки нельзя считать ссылку на prefab, коллайдер, слои и геометрию хранения проверенными. Полная иерархия игровых prefab в изученных материалах не подтверждена. Метод `MreDecaySafeBuilder.BuildVisualBundle` экспортирует исключительно визуальный bundle в заранее созданный каталог `MRE_SAFE_VISUAL_OUTPUT`, не игровой предмет.

Владелец уточнил: большому сейфу достаточно 300 клеток с обычным ограничением количества отдельных предметов, обход лимита не нужен. По проверке установленной игровой DLL координатором обычный путь ограничивает страницу 200 отдельными предметными записями; 300 клеток не означают возможность положить 300 предметов 1×1. Это ещё требует проверки игровым сценарием и сохранением.

В официальном локальном `ExampleAssets.unitypackage` объект Locker не найден; изучен пример `Crate_Maple`: `Item` использует layer 13/tag Item, `Icon`, BoxCollider и LOD; `Barricade` — layer 27/tag Barricade, BoxCollider и LOD, отдельно присутствуют `Nav` и `Animations`. Код `BuildExperimentalStorage` создаёт собственные Item/Barricade из примитивов с аналогичными слоями, тегами и коллайдерами и отдельные экспериментальные bundle. Он не копирует модели примера. `Nav` и `Animations` представлены экспериментальными заглушками; LOD и точное игровое разрешение bundle не реализованы и не проверены; bundle нельзя считать готовым игровым ресурсом. Временный экспорт выполнен Unity 2022.3.62f3 с exit code 0 и маркером `MRE_SAFE_EXPERIMENTAL_OK`; загрузка Unturned и сохранение не проверялись.

## Инструментальная проверка реестра и серверных prefab, 04.11.2026

Временный Rocket-плагин `checks/SafeDiagnostic.cs` запущен только в `%TEMP%/mre-safe-u3ds-isolated`, сервер `SafeTest`, PID 18876. После загрузки PEI диагностика запрашивала `Assets.find` отдельно по каждому ID и GUID. Все три пары разрешились в один и тот же объект типа `SDG.Unturned.ItemStorageAsset`: 60971 / `bf233036b60d403c836deb8ac0f03292` — 10×10; 60972 / `1668b7ad4220431488a714a85719c1ee` — 10×20; 60973 / `3b716600a696477487302a6faf595464` — 15×20. У каждого серверная ссылка `_barricade` разрешилась в объект `Barricade`, а `_nav` — в `Nav`; у каждого из этих объектов диагностирован один collider. Журнал проверки: [server-evidence-2026-11-04.txt](checks/server-evidence-2026-11-04.txt).

Серверные экземпляры `Barricade` имеют ноль Renderer, поле `_item` равно null; режим `-nographics` сам по себе не доказывает визуальную корректность на клиенте. Отображение модели, доступность Item-prefab на клиенте, размещение и открытие не проверены. Серверный журнал не содержит ошибок или исключений; Unity-журнал headless сообщает ошибки неподдерживаемых шейдеров, поэтому визуальную работоспособность по нему подтвердить нельзя. Диагностика вызвала `shutdown`, журнал подтвердил сохранение и завершение, процесс отсутствует; тестовая DLL удалена из изолированного сервера после сверки хеша. Исходник диагностики сохранён для воспроизводимости; его нельзя устанавливать на рабочий сервер, поскольку он автоматически выключает сервер.

Повторение возможно только на отдельной копии U3DS с тестовым миром и отдельным портом. Исходник компилируется Roslyn `csc.dll` из установленного .NET SDK с `/noconfig /nostdlib+ /target:library /langversion:7.3` и ссылками из копии сервера: `Unturned_Data/Managed/{mscorlib,System,System.Core,netstandard,System.Runtime,Assembly-CSharp,UnityEngine,UnityEngine.CoreModule,UnityEngine.PhysicsModule,com.rlabrecque.steamworks.net}.dll` и `Extras/Rocket.Unturned/{Rocket.API,Rocket.Core,Rocket.Unturned}.dll`. Полученный `SafeDiagnostic.dll` помещают в `Servers/SafeTest/Rocket/Plugins` только проверенной изолированной копии, запускают `Unturned.exe -batchmode -nographics -NoDefaultConsole -logfile <отдельный-путь> +LanServer/SafeTest` и после выхода сверяют журнал и PID. Через 65 секунд после загрузки плагин выводит результат и выполняет `shutdown`; никакой сервер с нужным миром для этого не применять. Временные тестовые `.dat` и bundle находятся в `%TEMP%/mre-safe-u3ds-isolated/Servers/SafeTest/Bundles` и не являются утверждённым пакетом.

Полные журналы без копирования игровых данных в репозиторий: `%TEMP%/mre-safe-u3ds-isolated/Logs/Server_SafeTest.log` SHA-256 `7888b73da90ae65f0317a2970ea996e16223abc3252b21629a5085845ec193ac`; `%TEMP%/mre-safe-diagnostic/unity.log` SHA-256 `e3eef3681f4e9ce0dc0238e0523cb91466311f31712c2ddd96723253193da2b1`. Для сравнения: тестовая DLL диагностики SHA-256 `9ed0d430e792b09f5bbdcfce679256a41820093bd11cfbc9a7bacb029f2c5b85`, игровая `Assembly-CSharp.dll` SHA-256 `15666f1e20afc32a01a5510eb71eef2512a6eb4064ee628b806ee333ab4e4660`. Журналы в TEMP могут быть перезаписаны следующим запуском.

`Animations` в текущем генераторе — пустой GameObject с компонентом Animation без клипов. В серверном тесте эта заглушка не доказывает, что предмет можно взять в руки и разместить: клиентский путь экипировки и проигрывание клипов не исполнялись, а специфический контракт и последствия отсутствующих клипов не установлены. Для ответа нужен анализ клиентского кода и отдельный игровой тест с собственным ресурсом; до них считать предмет неготовым.

## Анимации и изолированная сборка, 05.11.2026

Текущее состояние: экспериментальные сейфы не прошли клиентскую приёмку и не готовы к установке на рабочий сервер. Предыдущие сведения о пустом `Animations` относятся к сборкам до 05.11.2026. В генераторе теперь создаются собственные legacy-клипы `Equip` (0,4 с) и `Use` (0,5 с), с кривыми вращения рук. Пути костей взяты из анализа локального официального `ExampleAssets.unitypackage`: у `Crate_Maple/Animations.prefab` два клипа, `Equip` и `Use`, из FBX Barricade, привязанные к `Skeleton/Spine/{Left,Right}_Shoulder/...`. Модели, клипы и ключевые кадры примера не копируются. Кривые MRE являются экспериментом: соответствие позы и положения модели игроку не доказано.

[Документация SDG](https://docs.smartlydressedgames.com/en/stable/items/introduction.html), проверена 05.11.2026: экипируемому предмету нужен prefab `Animations` с компонентом Animation и клип `Equip`. Установленный игровой код `UseableBarricade` также проигрывает `Use` и читает его длительность; проверка кода не заменяет игровой запуск. [Официальный U3-SDK](https://github.com/SmartlyDressedGames/U3-SDK) указывает Unity 2022.3.62f3.

Воспроизведение: `powershell -ExecutionPolicy Bypass -File scripts/Build-MreDecaySafe.ps1`. Скрипт создаёт новый каталог в TEMP, копирует туда исходники Unity, собирает три Windows bundle и печатает SHA-256 и путь. `-Unity` задаёт другой исполняемый файл; `-WorkDirectory` принимает только ещё не существующий путь внутри TEMP. Рабочий сервер и мир скрипт не меняет; публикация не выполняется. После сборки Unity повторно открывает каждый bundle и проверяет наличие legacy-клипов, ненулевую длительность и кривые; это не проверка скелета в клиенте.

В Unity 2022.3.62f3 сборка прошла с exit code 0: все шесть проверок `MRE_SAFE_CLIP_OK` и `MRE_SAFE_EXPERIMENTAL_OK`. Путь результатов: `%TEMP%/mre-safe-build-9ef5fada716a4740b8fc27470c2c6e23`, журнал повторной проверки `verified.log`. SHA-256 bundle 100/200/300: `425520b8a1e367f2157e166a476e51f729ca087b70829ba6f17168748f408dbb`, `63c06969a79f4819268d0350fed9122a9137d74f893052ee20b0f40aedc6ad0f`, `8bac59174b9b4451e7968f870581888bacf82a9393666a40acc8185ea7a5cd54`.

Осталось проверить клиентом модель, анимации, размещение и открытие всех сеток, заполнение с нативным пределом 200 отдельных записей, перезапуск, восстановление и отсутствие дюпа. Сетки задают 100/200/300 клеток, а не гарантию 300 отдельных предметов. Без этих сценариев выпуск и использование для ценных предметов не подтверждены.

Отдельная копия `%TEMP%/mre-safe-anim-isolated-20261105`, сервер `SafeAnim`, порт 27960 и новый тестовый мир: диагностический плагин разрешил каждый из трёх ID и GUID в один `ItemStorageAsset`, прочитал соответственно 10×10, 10×20, 15×20, а также серверные `Barricade` и `Nav` с одним collider каждый. Уровень загружен, диагностический процесс PID 18516 запросил штатное выключение; журнал фиксирует сохранение тестового мира и завершение, процесса больше нет. Проверка не выполняла вход клиента, размещение предметов, сохранение их содержимого или restore. Рабочий сервер и его мир не использовались.

Полные журналы находятся только в TEMP: `Logs/Server_SafeAnim.log` SHA-256 `6832b6fe54878a047e291af6755b91c58fab627f995054525058cab4473f0190`; `safeanim-unity.log` SHA-256 `b5b8e5c9857e02e66e383503054421dc20898ddee3fe437362cfe7597b4c5626`. Серверный путь не проверяет клиентские клипы или визуализацию; автоматическое выключение тестовой диагностикой не следует применять к рабочему серверу.
