# MreHud: HUD, телепортация и голосование

Оригинальный серверный плагин MRE для LDM/Rocket. Использует текущие проверенные сборки `Teleportation.dll` из `src/Teleportation.MRE` и `MreEssentials.dll` с публичным snapshot голосования. Исходники MreHud — MIT, см. [LICENSE](LICENSE). Игровые DLL используются только как ссылки при сборке.

## Что показывает

- Здоровье, еду, воду, энергию и появляющийся при нехватке кислород. Собственный индикатор иммунитета убран; отключение его игровой механики реализуется отдельно в MreImmunity.
- Кровотечение, перелом, действующий combat/raid block. Остальные штатные значки, транспорт, компас, чат и прицел остаются под управлением игры.
- Название оружия и установленного магазина, фактические патроны и вместимость, режим стрельбы и прочность оружия. Отсутствующий магазин отличается от неизвестного состояния. Число после `/` — вместимость магазина, **не запас патронов в инвентаре**.
- Входящий и исходящий TPA, имя второго игрока, срок ответа, действия через Plugin Key. После принятия — серверный отсчёт и прогресс у обоих участников. Никакой отдельной логики переноса в UI нет.
- Аналогичный отсчёт `/home`: имя дома, оставшиеся секунды, прогресс и отмена на Ю. Источник данных — `TeleportationPlugin.GetHomeUiRequest`; кровать и перенос контролирует MoreHomes.MRE, движение не требуется останавливать.
- Общесерверное `/vote day`: тему и инициатора, голоса за/необходимое число, участников, оставшееся время, подсказку `/vote yes` или `/cv`. После решения отображается результат. Срок показа результата и допуск конкретного игрока определяет MreEssentials; UI не пересчитывает кворум и не проводит голосование самостоятельно.

В Unturned стандартные Plugin_0/Plugin_1 — физические Б/Ю (Comma/Period). Подписи по умолчанию содержат `<plugin_0/>` и `<plugin_1/>`: клиент подставляет действительные привязки. При изменении индексов в Teleportation меняют соответствующие токены конфигурации HUD. Курсор, Modal и блокировка движения не включаются.

## Сборка

```powershell
.\src\Teleportation.MRE\Build.ps1
.\scripts\Build-MreEssentials.ps1
.\scripts\Build-MreHud.ps1
dotnet run --project .\src\MreHud\Checks\MreHud.Checks.csproj --configuration Release
```

DLL и manifest находятся в `runtime/plugin-builds/MreHud`. Manifest сохраняет SHA256 обеих серверных зависимостей. Скрипт не изменяет работающий сервер и не копирует DLL. Компиляция выполняется по фактическим `Assembly-CSharp.dll`, `SDG.NetTransport.dll`, Unity и LDM установленного U3DS. Сборка клиентского uGUI описана в [ui/MreHud](../../ui/MreHud/README.md).

## Безопасное включение

`Enabled=true`, **`AssetsVerified=false`**, **`HideNativeHud=false`**. При этих значениях плагин загружается, но не показывает неготовый интерфейс. Отсутствующий EffectAsset или несовпадение ID/GUID оставляют штатный HUD. Сам факт компиляции DLL не подтверждает наличие UI на клиенте.

После сборки и доставки bundle сначала проверить его с подключённым тестовым клиентом при `AssetsVerified=true, HideNativeHud=false`. Только после наблюдаемой проверки здоровья, патронов и TPA включать `HideNativeHud=true`. Этот параметр скрывает лишь заменённые life meters и gun status; остальные игровые элементы не трогает. При ошибке интерфейс отключается для текущего подключения, изменённые флаги восстанавливаются. При выгрузке плагина флаги восстанавливаются, custom effect очищается.

Плагин отправляет только изменившиеся значения, выполняется на главном Unity-потоке, проверяет игроков примерно каждые 100 мс. Все обращения к effect идут конкретному соединению, а не всем игрокам. Имена ограничены и не интерпретируются как rich text.

## Статус

Серверная компиляция и чистая логика проверяются отдельно от Unity. На 30.10.2026 Unity Editor в рабочей среде отсутствует: генератор есть, готовый `.unity3d` и игровая приемка пока отсутствуют. Без клиентского bundle кастомный UI в игре не появится. Наблюдаемые результаты проверки фиксируются в [UI_VERIFICATION.md](../../docs/UI_VERIFICATION.md).
