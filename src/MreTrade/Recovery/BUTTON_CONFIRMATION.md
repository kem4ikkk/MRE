# Подтверждение обмена с проверкой версии

Игровое событие `onEffectButtonClicked` передаёт серверу игрока и имя кнопки; идентификатор окна и версия предложения в событии отсутствуют. Поэтому один постоянный `TradeConfirm` не позволяет отличить задержанный клик от нового. Ожидание, повторное открытие окна или простое обнуление подтверждений не решают проблему.

Внедрён безопасный двухшаговый вариант: кнопка `TradeConfirm` называется «Получить код» и только выдаёт команду с GUID сессии и ревизией предложения. Игрок сверяет обе стороны через `/trade list`, затем отправляет `/trade confirm <код_сессии> <версия>`. Сервер сравнивает оба значения до установки подтверждения. Изменение предложения увеличивает ревизию; новая сессия получает новый GUID. Задержанный клик может выдать актуальную команду, но сам ничего не подтверждает.

Одно нажатие, которое сразу подтверждает текущую версию, всё ещё невозможно строго реализовать с нынешним callback: он передаёт только повторно используемое статическое имя `TradeConfirm`. Для такого поведения требуется клиентское событие с токеном или пул уникальных имён кнопок с долговременным одноразовым счётчиком; ограниченный пул увеличивает размер интерфейса и исчерпывается.

Модельный тест проверяет устаревшую ревизию, чужой SteamID, повторное подтверждение и предыдущую сессию. Независимая проверка Sol не нашла блокеров в логике токена. Игровые задержанные RPC и два клиента ещё не проверены. Аварийная сохранность инвентарей остаётся отдельным блокером; включать обмен для ценных предметов нельзя.
