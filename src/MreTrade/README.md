# MreTrade — тестовый обмен предметами

`/trade` запускает обмен двух игроков на любом расстоянии. В чате используются только запрос `/trade <ник>` и ответ получателя `/trade accept` или `/trade deny`; выбор предметов, подтверждение и отмена выполняются в окне обмена. Игроки выбирают существующие предметы из своего личного инвентаря; вещи не изымаются при создании предложения. Обе стороны подтверждают обмен. Изменение предложения сбрасывает оба подтверждения. Пустой обмен отклоняется, максимальное количество выбранных предметов — 10 на сторону. Сессия истекает через пять минут с запроса. При отмене до обмена вещи остаются у владельцев.

На первом этапе реализация предназначена **только для отдельного тестового сервера и тестовых вещей**. Обмен по умолчанию отключён (`ExperimentalTradeEnabled=false`); для испытания на изолированной копии необходимо явно установить `true`. Реальный игровой прогон двумя клиентами, восстановление после сбоев и совместимость со сторонними плагинами ещё не подтверждены; использовать на публичном сервере или для ценных вещей до приёмки нельзя.

## Команды и окно обмена

1. Инициатор вводит `/trade <ник>`. Указанный игрок должен быть онлайн и свободен от другого обмена; используется точное имя, чтобы запрос не ушёл другому игроку.
2. Получатель вводит `/trade accept` для принятия или `/trade deny` для отказа. После принятия сервер открывает окно обмена обоим игрокам.
3. В окне каждая сторона нажимает свою ячейку `TradeOwnSlot`, открывает нативный инвентарь и выбирает предмет. Свои выбранные предметы можно убрать повторным действием в UI; предложение партнёра доступно только для просмотра. Предмет в руках нужно сначала убрать; надетая одежда и оружейные слоты не входят в обмен.
4. После проверки обе стороны нажимают кнопку «Подтвердить обмен». Изменение любого предложения увеличивает версию и сбрасывает подтверждения и отметки просмотра обеих сторон; UI обновляется, и каждый должен проверить актуальный состав заново. Кнопка «Отменить» закрывает сессию до начала передачи. Текстовые операции выбора, подтверждения и отмены не являются игровыми командами этого потока.

Количество и качество показываются в окне, но вложенное состояние предмета — патроны, прицелы и другие модификации — **не расшифровывается в интерфейсе**. Перед обменом проверяйте эти свойства отдельно; сервер пытается сохранить байты состояния без изменений, но факт сохранности проверяется игровым испытанием.

## Бой, рейд и права

Обоим игрокам требуется право `mre.trade`, включённое только в шаблон default-группы. Если сервер уже установлен, после резервной копии добавьте право точечно в действующий `RocketPermissions.xml`: установщик TradeOnly не меняет существующие права. Сессия отклоняется/отменяется при смерти, отключении, открытом контейнере, отсутствии прав, недоступности проверок Teleportation и при combat/raid блоке любого участника.

Используются *текущие настройки и проверки Teleportation*, не новые 60/180 секунд. При входе и загрузке плагина обмен временно закрыт на максимум настроенных `CombatDuration`/`RaidDuration`, чтобы не снять активную блокировку простым reconnect. Это дополнительная выдержка и может задержать обмен даже вне боя. Если конфиг повреждён, блокировки Teleportation недоступны или их обход разрешён, обмен закрыт.

Существующий raid guard не покрывает все рейды: его таймер касается атакующего при онлайн-владельце или группе базы; защитник, offline-база и радиус вокруг неё им не подтверждены. Он также сбрасывается после перезапуска плагина. Поэтому нельзя считать защиту от рейда полной; требования владельца о запрете обмена при любом рейде не приняты без отдельной доработки и испытаний.

## Сохранение и восстановление

Перед переносом создаётся запись `Servers/MRE/Rocket/Plugins/MreTrade/transactions/<операция>.pending` и блокировки SteamID. В ходе переноса проверяется состояние обоих инвентарей и ряд известных путей добавления/выброса; при синхронной ошибке выполняется обратный перенос только если состояние остаётся известным. При неопределённой ошибке автоматический повтор не выполняется, блокировки остаются. Любой файл `.pending` блокирует все новые обмены, даже если lock-файл отсутствует. При штатном завершении записываются `.done` и снимаются lock-файлы.

Сохранение двух игровых инвентарей и файлов журнала **не является одной атомарной транзакцией**. Авария, в том числе после снятия lock-файлов, может привести к потере или дублированию. Текстовые/игровые снимки и журнал не гарантируют автоматического восстановления. Прямое изменение игровых полей сторонним плагином и поведение клиентов вне проверенных API не охвачены полностью. При ошибке сохраните неизменённые журнал, логи, снимки и резервную копию обеих сторон; не выдавайте вещи повторно и не удаляйте lock/pending до ручной сверки. Журнал, состояние мира и инвентари должны входить в согласованную копию.

При запуске наличие любого старого `.pending`, `.done` или `.lock` блокирует все обмены до ручной сверки и следующего перезапуска. Это касается и штатных перезапусков после успешных обменов; любой одиночный `.lock` также блокирует журнал целиком. Остановка новых обменов не возвращает предметы и не предотвращает перемещение уже созданных копий. Для сверки остановите сервер, сохраните неизменённые журналы, логи, оба сохранения игроков и согласованную резервную копию, затем сопоставьте результаты с журналом. Только после разрешения каждого спорного случая архивируйте проверенные записи и соответствующие lock-файлы вне каталога `transactions` и перезапустите сервер. Автоматически повторно предметы не выдаются. Процедура и поведение игры после аварии пока не испытаны.

Для анализа копии журнала доступен [офлайн-инспектор](Recovery/README.md). Его результат содержит SteamID и сведения об инвентарях, поэтому храните его как приватные данные; инструмент только читает файл и не производит восстановление.

## Сборка и тестовая установка

Нужны .NET SDK, PowerShell, U3DS с LDM и Harmony, а также совместимый Teleportation.MRE. На ПК в корне проекта сперва соберите Teleportation для тех же DLL, затем MreTrade:

```powershell
.\src\Teleportation.MRE\Build.ps1
.\scripts\Build-MreTrade.ps1
.\scripts\Install-MreFeatures.ps1 -TradeOnly
```

Последняя команда только проверяет сборку и манифест. Для отдельной **тестовой** копии после штатной остановки сервера и резервного копирования используйте ` .\scripts\Install-MreFeatures.ps1 -TradeOnly -Apply `. Она не перезаписывает файл прав. Убедитесь, что на сервере загружена та же сборка Teleportation, по которой собирали MreTrade, и нужное право добавлено в работающий конфиг. Для нестандартного пути U3DS скрипт сборки принимает `-GameDirectory`.

Автоматические изолированные проверки:

```powershell
dotnet run --project src/MreTrade/Tests/MreTrade.Tests.csproj
dotnet run --project src/MreTrade/DeliveryChecks/MreTrade.DeliveryChecks.csproj
dotnet run --project src/MreTrade/RecoveryChecks/MreTrade.RecoveryChecks.csproj
```

Первая проверяет состояния подтверждения, вторая — обнаружение повторной вставки в поддельном API; ни одна не проверяет реальный Unturned, фактические Harmony-патчи или аварийное восстановление. Проверка сборки по reference DLL не доказывает совместимость с DLL установленного сервера. Сценарии для двух клиентов — в `docs/TRADE_TEST_PLAN.md`.
