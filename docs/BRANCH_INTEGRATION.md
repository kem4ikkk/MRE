# Объединение веток MRE — 1 ноября 2026

Рабочей основой при интеграции были локальные версии Essentials, HUD, Teleportation и MreKits. Из `feature/start-kit-chat-icon` и включающей её `draft/vault-s` выборочно перенесены иконка и серверные сообщения, стартовый набор и тестовый прототип `/s`. Эти исходники фиксируются в общем коммите проекта; история веток не объединялась и отправка на удалённый сервер этим не подтверждается.

## Что объединено

- Сохранены локальные `/vote day` при одном игроке, максимальные навыки и API для HUD. Старый Essentials из ветки не установлен.
- `start` содержит согласованный владельцем набор и задержку 3600 секунд; `claims.json` сохранён. Имя журнала `starter` используется для старых блокировок и незавершённых выдач. Одежда надевается в свободные слоты; после неудачи при надевании требуется ручная сверка, автоматического повтора нет.
- Текстовые серверные сообщения используют иконку из commit `59d6b05`; ссылка проверена HTTP 200. Шаблоны MoreHomes и Teleportation обновлены. Текущие конфиги этих двух установленных плагинов не менялись, поэтому их иконка на сервере может отличаться до отдельной установки настроек.
- `/s` установлен **только для локального испытания**, игрокам выдано право `mre.vault`. Проверка права повторяется в открытой сессии. Маркер `.initialized` помогает обнаружить пропажу файла ранее сохранённого хранилища, если сам маркер не потерян.

## Проверки

- Семь модулей (Essentials, Flight, Interface, InventoryAudit, Moderation, Kits, Vault) собраны в изолированной директории против DLL локального U3DS. Компиляция не доказывает работоспособность в игре.
- Тесты журнала и транзакции MreKits: 15 PASS, включая сохранение старого cooldown/pending при смене имени. Настоящий Unity-инвентарь тестами не покрыт.
- Тесты VoteSession, LocalControlBridge и MaxSkillsPolicy: 57 PASS. Тесты файла и ограниченного журнала VAULT: PASS, включая отсутствие файла при сохранённом маркере. Реальный игровой runtime и аварии тестами не покрыты.
- Локальные поведенческие тесты Teleportation: 76 PASS (43 TPA и 33 HOME); игровой runtime ими не проверяется.
- Установщик: 32 PASS на фиктивном изолированном экземпляре. Подтверждена совместимость сборок Kits/Vault по SHA256 установленного Teleportation.
- До установки мир штатно сохранён; создан архив `backups/MRE-pre-test-20261101-031950-5121.zip` с манифестом и 2292 файлами. SHA256 Essentials, HUD, Teleportation, MoreHomes и Interface до и после установки совпадает. После установки сервер загрузил PEI; A2S ответил на 127.0.0.1:27015, 24 слота. В журнале зарегистрированы `/kit`, `/kits` и `/s`. Игрок подключился и выполнил `/kit start`; в журнале наборов появилась одна завершённая запись, `pending` отсутствует. Состав выданных вещей и поведение cooldown это само по себе не подтверждает.
- Метаданные установленной Assembly-CSharp содержат все три целевых метода Harmony и параметр `page` у `ReceiveDropItem`; это не проверка игровых сетевых путей.

## Ограничения и следующий шаг

`/s` — прототип: игровой инвентарь и файл VAULT не образуют общую транзакцию. После аварии возможны потеря и дюп; `.pending` не содержит полных снимков, а тестируемый `VaultJournal` пока не подключён к runtime. Проверить только тестовыми вещами, не продавать и не использовать для ценного лута. Пропажа одновременно `.vault` и `.initialized` не обнаруживается. Ограничения raid block Teleportation сохраняются.

Фактические состав выдачи, укладка, одежда, повтор по времени, содержимое `/s`, закрытие, обрыв соединения, рестарт и восстановление не подтверждены. Перед публикацией нужны сценарии из `VAULT_TEST_PLAN.md` и независимая проверка GPT-6.1 Sol: запуск агентов в сессии интеграции был недоступен. Предыдущая проверка веток Sol не является проверкой новых объединённых изменений.

Копия мира находится на том же компьютере. Игровые сохранения, права и секреты в репозиторий не добавлять. Перед обратным переключением DLL восстановить согласованные данные и конфигурацию по `LOCAL_OPERATIONS.md`; не смешивать состояния, полученные в разные моменты.
