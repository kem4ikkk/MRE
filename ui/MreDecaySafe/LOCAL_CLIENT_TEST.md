# Локальная проверка ресурсов через тестовую карту

Статус на 05.11.2026: подготовка и серверная часть испытаны, клиентская загрузка и подключение не проводились. В [ответе разработчика SDG от 2 мая 2023](https://github.com/SmartlyDressedGames/U3-SDK/issues/3836) предложено тестировать собственный контент без загрузки в Steam в `Bundles` загружаемой тестовой карты, имеющейся в `Maps` на клиенте и сервере. Это не автоматическая доставка: одинаковую тестовую карту нужно заранее предоставить каждой стороне. Официальная [документация сервера](https://docs.smartlydressedgames.com/en/stable/servers/server-hosting.html) описывает автоматическую загрузку клиентом именно для Workshop File ID. Непубликуемый контент не следует выдавать за опубликованный Workshop-мод или присваивать ему чужой File ID.

1. Собрать совместный пакет `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-MreDecaySafeClientPackage.ps1` и сохранить путь `collection` и `SHA256SUMS.txt`. Для эксперимента использовать только собственные ассеты. Экспорт Windows, совместимость с другими ОС не проверена.
2. Подготовить временную тестовую карту: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-MreDecaySafeTestMap.ps1 -Collection <путь-к-collection> -MapSource <путь-к-отдельной-тестовой-карте>`. Скрипт только читает исходники и создаёт новый каталог TEMP `MREDecayTest` с `Bundles`; не принимать путь к уже существующей рабочей папке, скрипт не выполняет установку. Он откажется от исходной карты с существующим `Bundles`, чтобы не смешать ресурсы. SHA-256 всех файлов скопированной карты — в соседнем `SHA256SUMS.txt`. Не публиковать и не распространять сторонние карты без соответствующих прав.
3. В отдельной копии U3DS с отдельными миром, serverID и портом разместить тестовую карту в `Maps/MREDecayTest`, выставить `Map MREDecayTest` в его `Server/Commands.dat`. Запустить только эту копию; журнал должен подтвердить обнаружение карты, добавление `Maps/MREDecayTest/Bundles`, четыре map assets и готовность уровня. Файлы рабочей карты и сервера не заменять. Перед каждым тестом сверять все хеши и резервировать только тестовый мир.
4. Для будущего клиентского испытания потребуется отдельная тестовая копия клиента и такая же тестовая карта в её `Maps/MREDecayTest`; заранее проверить хеши всех файлов на обеих сторонах. На работающем или основном клиенте файлов не менять. Проверить вход на тестовый сервер, наличие иконок и моделей, анимацию, установку/открытие сейфов, сетки и доступы. Совместимость пути и проверка сетевой целостности клиентом пока не подтверждены: при ошибках сохранить логи и не отключать механизмы проверки. Подсказка остаётся невидимой без отдельно подключённого и проверенного сервера, который отправляет эффект. Подробные сценарии хранения и дюпа — [ACCEPTANCE.md](ACCEPTANCE.md).
5. Удалять только созданную тестовую копию после завершения её процессов и сверки пути; рабочие клиент и сервер скрипт не затрагивает. Переход на настоящий сервер — отдельный этап с новой проверкой конфликтов, резервной копией и планом отката.

Выполненная серверная проверка: оригинальную PEI из изолированной копии U3DS скопировали в `%TEMP%/mre-decay-map-stage-307cf5da10184f7e9449d688de8ca2d6/MREDecayTest` исключительно для локального теста. Все 106 исходных файлов совпали по SHA-256; добавлены 11 файлов пакета. SHA-256 `SHA256SUMS.txt`: `103317450ae91409d19b7380651f556182a7f0e21534e2e9f2c478732a2ef0dd`. Карта используется только локально, её перепубликация не выполнялась.

На сервере `MREMapPackage` в отдельной U3DS-копии с портом 28040 журнал подтвердил путь `Maps/MREDecayTest/Bundles`, четыре map assets и загрузку уровня. [SafeMapPackageDiagnostic.cs](checks/SafeMapPackageDiagnostic.cs) после загрузки разрешил три сейфа и effect по ID/GUID, затем сервер штатно выключился. Журнал `%TEMP%/mre-safe-anim-isolated-20261105/Logs/Server_MREMapPackage.log`, SHA-256 `f64f0c9c13b15490c233a7b17f3ee2e62e1b648be77d058477139f8194e6d416`. Первый запуск ошибочно использовал диагностику с другим serverID: она корректно отказалась выполнять проверку; его журнал сохранён как `map-package-first-refusal.log`, процесс теста адресно завершён, затем повторено с правильным guard. Это не клиентская приёмка. Клиент и рабочий сервер не изменялись.
