## Установка с нуля

Нужны Windows x64, Windows PowerShell 5.1 и установленный .NET SDK для компиляции собственных плагинов. Русские PowerShell-скрипты сохранены UTF-8 с BOM.

```powershell
.\scripts\Install-MreServer.ps1 -Validate
.\scripts\Initialize-MreServer.ps1
.\scripts\Install-MrePlugins.ps1
.\scripts\Build-MreUi.ps1
.\scripts\Build-MreKits.ps1
.\scripts\Install-MreUi.ps1 -Apply -IncludeKits
.\scripts\Start-MreServer.ps1 -WaitForReady -TimeoutSeconds 240
.\scripts\Stop-MreServer.ps1
.\scripts\Set-MreWorkshop.ps1 -Apply -IncludeVehicles
.\scripts\Start-MreServer.ps1 -WaitForReady -TimeoutSeconds 240
```

Первый запуск создает WorkshopDownloadConfig.json. Предварительный `Install-MrePlugins.ps1` проверяет закрепленные исходные архивы и подготавливает Harmony. `Build-MreUi.ps1` собирает Teleportation → MoreHomes MRE → MreEssentials → MreHud; `Build-MreKits.ps1` отдельно собирает наборы. Затем `Install-MreUi.ps1 -Apply -IncludeKits` проверяет manifests/хеши и устанавливает весь серверный комплект с резервными копиями прежних DLL. Отдельная ручная сборка и копирование MreEssentials не требуются. Версии и хеши — в [plugins.lock.json](../plugins.lock.json), снимок сборки — в [release-manifest.csv](../release-manifest.csv).

Для обновления существующего экземпляра сначала корректно остановите MRE и сделайте резервную копию по [инструкции эксплуатации](LOCAL_OPERATIONS.md), затем повторите сборку и `Install-MreUi.ps1 -Apply -IncludeKits`. Установщик не заменяет настройки MreEssentials и наборов; сервер не должен работать во время применения DLL.

`Initialize-MreServer.ps1` по умолчанию не заменяет существующие Commands.dat, Config.txt и права. Для применения базовых шаблонов использовать `-UpdateConfiguration` только после остановки и копии; прежние файлы сохраняются рядом. Существующие группы и участники не заменяются. Настройки плагинов сохраняются по умолчанию; их обновление требует `Install-MrePlugins.ps1 -Apply -UpdateConfiguration`.

Граница готовности UI на 31.10.2026: **backend установлен**, но собственный интерфейс еще не отображается без клиентского ресурса. MreHud устанавливается с `AssetsVerified=false`, `HideNativeHud=false`, поэтому штатные показатели остаются доступны. Для custom UI нужны экспорт собственного Unity bundle, доставка клиенту по [инструкции](../ui/MreHud/README.md) и игровая приемка. Установка DLL не подтверждает эти этапы. Выполненные проверки и оставшиеся сценарии — в [UI_VERIFICATION.md](UI_VERIFICATION.md).

## Подключение и команды

На этом компьютере: IP **127.0.0.1**, порт **27015**, **без пароля**. Поле пароля в клиенте оставьте пустым. Для друзей текущий Server Code находится в `runtime/server/Logs/Server_MRE.log`. Без GSLT код меняется после перезапуска; доступ из чужой сети еще не проверен.

Игровые команды: `/home`, `/home cancel`, `/homes`, `/renamehome`, `/destroyhome`, `/tpa`, `/tpa a`, `/tpa d`, `/kits`, `/kit starter`, `/vote day`, `/vote yes`, `/vote status`, `/cv`. HOME привязан к кроватям, а не к произвольной точке `/sethome`.

Голосование: только ночью, минимум один игрок, 60% от зафиксированного состава участников, длительность 60 секунд, cooldown 300 секунд. Право — `mre.vote`. Один игрок проходит голосование своим первым голосом; сервер хранит результат для UI еще 8 секунд. Показ карточки требует клиентского bundle. Это собственная реализация MRE; точное поведение REDLINE `/vote day` не подтверждено.

```powershell
.\scripts\Test-MreServer.ps1
.\scripts\Send-MreServerCommand.ps1 -Command Diagnostics
.\scripts\Send-MreServerCommand.ps1 -Command Save
.\scripts\Stop-MreServer.ps1
.\scripts\Backup-MreServer.ps1 -Name MRE-before-change
```

Диагностика — `runtime/control/MRE/diagnostics.json`. Локальный мост принимает фиксированный список команд, не слушает сетевой порт и защищен NTFS-правами владельца Windows, SYSTEM и администраторов. Игрок не получает доступ к нему через чат. RCON LDM отключен.

## Что не проверено и не подключено

Чистый клиент, два настоящих игрока, пятый участник группы, кровати, PvP/рейд в Unity, голосование в игре, рецепты, спавн транспорта и нагрузка 12/24. VAULT отсутствует. Существующий raid block не является общей защитой всех хранилищ и не охватывает радиус/защищающихся.

Custom UI здоровья, патронов, HOME/TPA и голосования требует собранного Unity bundle и его доставки подключающемуся клиенту. Эти клиентские этапы и реальная отрисовка пока не подтверждены; установленный backend и успешная сборка C# их не заменяют.

Автодонат: подтверждены официальные команды и схема конфигурации, но магазина владельца, ключей и проверенных платежей нет. Порядок — [AUTODONATE.md](AUTODONATE.md). Хостинг не куплен; деньги не списывались.
