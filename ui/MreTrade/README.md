# Оригинальное окно обмена MRE

**Локальный эксперимент:** `MreTradeBuilder.BuildWindowsExperimental` использует `runtime/maplestrike-extract/maplestrike-icon.png` и создаёт отдельный bundle с иконкой Maplestrike; сервер показывает её только для предмета ID 363. Прочие предметы остаются текстом. PNG получается отдельным рендером локально установленной модели и не входит в репозиторий или обычную сборку. Иконка не отображает обвесы и патроны. Экспериментальный и обычный bundle используют одинаковые идентификаторы и не должны загружаться вместе. Эксперимент не проверен в игре и не предназначен для публикации до проверки прав на ресурс. Обычный bundle содержит прозрачные пустые изображения, поэтому не показывает белые прямоугольники.

Отдельный Unity **2022.3.62f3** проект. Генератор создаёт uGUI окно: две стороны по десять предметов, сведения о партнёре, состояние подтверждений, кнопки подтверждения/отмены. Свои ячейки кликабельны, чужие — только текст. Иконки предметов не подменены картинками-заглушками: показываются серверные названия/количество. Выбор вещей выполняется отдельным серверным адаптером в нативном инвентаре; этот bundle сам не перемещает имущество.

В проекте нет игрового клиентского кода, EventSystem или закрытых ресурсов REDLINE. Шрифт — встроенный `LegacyRuntime.ttf`. В bundle стандартные Canvas, CanvasScaler, CanvasGroup, GraphicRaycaster, Image, Text, Button. Имена Button автоматически обрабатываются нативным `EffectManager.hookButtonsInUIEffect` Unturned. Canvas имеет sortingOrder=20, окно 1100×750 при reference resolution 1920×1080; сервер должен скрывать или очищать его при открытии нативного инвентаря, смерти, потере доступа и окончании сессии. Доставка и клики требуют проверки реальным клиентом.

## Контракт сервера

Effect ID **48622**, key **14822**, GUID **a986933995df4d29816efcc37f87b220**, адрес prefab **Effect**. Эти значения отличаются от существующего MreHud. Источник контракта — [effect-manifest.json](effect-manifest.json).

Текстовые поля: `TradePartner`, `TradeOwnOffer`, `TradePartnerOffer`, `TradeStatus`, `TradeOwn0`…`TradeOwn9`, `TradeOther0`…`TradeOther9`. Кнопки: `TradeConfirm`, `TradeCancel`, `TradeOwnSlot0`…`TradeOwnSlot9`. Корень видимости — `TradeContent`. Тексты не поддерживают rich text; длинные строки ограничиваются размером ячейки. Серверу следует выводить короткое имя, количество и качество; остальные сведения — отдельным описанием. Изменение любого предложения сбрасывает оба подтверждения на сервере, не в prefab.

Callback кнопки содержит имя, но не достоверный revision/token. Сервер обязан извлечь подключённого игрока из callback и проверить текущую сессию, собственника, её версию, обе стороны, сроки и combat/raid guard. Наличие кнопки и скрытие элементов не являются авторизацией. Если устаревший клик нельзя отличить, после изменения предложения требуется новая серверная последовательность подтверждения. Серверный адаптер находится в `src/MreTrade`; его перехваты и состояние сессии необходимо проверять на установленной версии сервера.

## Сборка на Windows

Открыть `ui/MreTrade` в установленном и активированном Unity 2022.3.62f3. Меню **MRE → Trade → Создать окно обмена** создаёт `Assets/MreTrade/Effect.prefab`; меню **Собрать Windows bundle** генерирует и проверяет свежий bundle. Либо:

```powershell
.\scripts\Build-MreTradeAssets.ps1 -UnityEditorPath 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe'
```

Результат: `runtime/ui-builds/MreTrade/Windows/MreTrade/{MreTrade.dat,MreTrade.unity3d}` и `bundle-build.json`. Скрипт проверяет версию Unity/платформу, свежесть результата, UnityFS, SHA-256 и идентификаторы. Editor повторно загружает bundle и проверяет адрес Effect, все имена полей, 12 кнопок, raycast/rich-text настройки. При ошибке Editor старый bundle не считается успешной сборкой. Без Unity executable сборка завершается понятным отказом; `.unity3d` не фабрикуется.

## Доставка и приёмка

Bundle нужен серверу и обоим клиентам. Предпочтителен отдельный собственный Workshop-пакет с сохранением GUID; здесь он не опубликован и Workshop ID не назначен. Существующий HUD, его файлы, ID и конфигурация не заменяются. Не устанавливать trade bundle в общий клиентский `Bundles` как встроенный core-ресурс: существующий MreHud уже выявил конфликт `invalid asset guid` при переходе на другие серверы. `Exclude_From_Master_Bundle` обязателен для legacy .dat; `Master_Bundle_Override` запрещён проверкой сборки. Фактическую структуру Workshop подтвердить чистым клиентом, без ручной глобальной копии.

Проверить двумя клиентами: вход и автоматическую доставку, разрешение кнопок только своей сессии, различимые предложения, отмену/изменение подтверждений, длинные имена, 1280×720/1920×1080/широкий экран, открытие и закрытие нативного инвентаря, отсутствие перекрытия штатных меню/курсора после закрытия, отключение партнёра, бой/рейд и невозможность поздним кликом подтвердить новую сессию. Asset build и браузерный preview не доказывают сохранность предметов или аварийный recovery.

Проверка исходного контракта без Unity: `python tests/CheckMreTradeUi.py`. Предпросмотр: [ui/trade-preview/index.html](../trade-preview/index.html). Дополнительный браузерный тест: `node tests/CheckMreTradePreview.cjs` при установленных Playwright и Chromium; путь к системному браузеру можно задать через `CHROMIUM_EXECUTABLE`. Тест поднимает временный сервер только на 127.0.0.1, проверяет 20 ячеек, свои кнопки, подтверждение, отмену, повторный старт и отсутствие горизонтального переполнения на 1920×1080 и 1280×720, затем закрывает сервер. Эти проверки прошли в среде разработки; Unity executable отсутствует, создание prefab/bundle и игровой прогон не выполнены. Это отдельная браузерная иллюстрация, не снимок игрового окна и не готовый клиентский bundle. Лицензия генератора и preview — MIT, см. [LICENSE](LICENSE).
