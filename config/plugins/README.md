# HOME и TPA для MRE

## UI-версия от 30.10.2026

По текущему запросу владельца подготовлены Teleportation MRE 1.8.3.3, MoreHomes MRE 1.10.3.1 и собственный MreHud. HOME и TPA используют отслеживаемый перенос с задержкой **5 секунд**, без отмены за движение. Входящий TPA принимается на **Б**, **Ю** отклоняет запрос либо отменяет HOME/TPA. Это стандартные физические клавиши Unturned; при переназначении UI выводит актуальный бинд. Chat fallback: `/tpa accept`, `/tpa deny`, `/tpa cancel`, `/home cancel`.

По последнему запросу владельца cooldown HOME — **80 секунд**, TPA — **100 секунд**. `/tpa a` принимает, `/tpa d` отклоняет входящий или отменяет исходящий перенос; длинные команды также доступны. Текущий MoreHomes XML: DefaultMaxHomes=2, DefaultHomeCooldown=80. Проверки combat/raid и действительности кровати сохраняются. HUD включает карточку `/vote day` с состояниями голосования и результатом на 8 секунд.

```powershell
.\scripts\Install-MrePlugins.ps1
.\scripts\Build-MreUi.ps1
.\scripts\Build-MreKits.ps1
.\scripts\Install-MreUi.ps1 -IncludeKits

# Применение только на остановленном MRE, с резервными копиями плагинов:
.\scripts\Install-MreUi.ps1 -Apply -UpdateConfiguration -IncludeKits
```

Предварительные команды проверяют сборку/хеши и настройки. Установщик MreHud не доставляет клиентский bundle и не включает скрытие штатных показателей. Исходный bundle собирается отдельно по [Unity-инструкции](../../ui/MreHud/README.md); Unity Editor в текущей среде отсутствует. `AssetsVerified=false`, `HideNativeHud=false` остаются до проверки настоящим клиентом. Визуальный [предпросмотр](../../ui/preview/index.html) работает локально в браузере. Старые разделы ниже описывают исходный baseline; актуальные UI-проверки — в [UI_VERIFICATION.md](../../docs/UI_VERIFICATION.md).

Проверено по официальным релизам и исходникам 29.10.2026. Здесь хранятся только несекретные настройки; игровые сохранения и DLL находятся в игнорируемом `runtime/`.

## Настройки

- HOME: одна привязанная кровать обычному игроку, две с `morehomes.vip`, три с `morehomes.elite`.
- HOME и TPA: ожидание 15 секунд, cooldown 300 секунд, отмена перемещения при движении отправителя.
- Оба уровня доната используют те же ожидания и блокировки, что и обычный игрок.
- CombatDuration — 60 секунд, RaidDuration — 180 секунд; AllowCombat/AllowRaid выключены.
- TPA-запрос ожидает принятия до 90 секунд. Принятый запрос отдельно ожидает 15 секунд и остается отменяемым.
- Телепортация в пещеру/под землю запрещена выбранными настройками; работоспособность с конкретными кроватями проверяется в игре.
- Русские сообщения записаны в файлы с суффиксом `.en.translation.xml`, потому что базовый язык Rocket — `en`. Это не английский текст сообщений.

Справочник точных прав — [permissions.json](permissions.json). Этот JSON не является файлом Rocket: права нужно слить с фактическим `Rocket.permissions.xml` текущего LDM. Установщик намеренно не заменяет права и не назначает игроков в платные группы. `restorehomes` остается административной командой.

## Известные границы

Исходный Teleportation 1.8.3 проверял combat/raid только у отправителя. MRE исправляет проверки получателя перед принятием и перед фактическим переносом, дублирование ожидающих запросов и отмену после отключения; описание изменения находится в [src/Teleportation.MRE/README.md](../../src/Teleportation.MRE/README.md).

Рейдовый таймер этого плагина включается у атакующего чужую базу с присутствующим онлайн владельцем/участником группы. Это не общий raid guard: нет радиуса, блокировки защитников, полноценной обработки offline-рейдов и блокировки VAULT/выдачи предметов. Эти свойства нельзя обещать на основании установленного Teleportation. HOME использует его combat/raid состояние.

Cooldown и combat/raid таймеры этих двух плагинов хранятся в памяти и после рестарта сбрасываются. Привязанные кровати MoreHomes сохраняются в `Servers/MRE/Level/PEI/MoreHomesData.json`; этот файл должен входить в согласованные резервные копии. Сроки платных групп, магазин, VAULT и автоматическая выдача покупок этими компонентами не реализованы.

## Воспроизведение

На остановленном сервере, после первого создания экземпляра MRE и установки штатного LDM:

```powershell
.\scripts\Install-MrePlugins.ps1
.\src\Teleportation.MRE\Build.ps1
.\scripts\Install-MrePlugins.ps1 -Apply
```

Первый вызов только скачивает/проверяет разрешенные файлы и XML. Применение использует общий `runtime/.mre-maintenance.lock`, проверяет отсутствие работающего U3DS и сохраняет заменяемые файлы в `backups/plugins-*`. Отличающаяся существующая конфигурация заменяется только с явным `-UpdateConfiguration`; иначе установка останавливается до изменения DLL.

Готовый бинарник исправления хранится в `runtime/plugin-builds/Teleportation.MRE/Teleportation.dll`, manifest — рядом в `build.json`. Установка копирует только Plugins/Libraries/configuration и лицензии; клиентскую установку Steam и фреймворк не изменяет. Полная игровая проверка проводится отдельно по чек-листу MRE.
