# Параллельные сессии MRE

Обновлено 30.10.2026 по явному указанию пользователя: графический UI делает другая сессия.

## Области текущей серверной сессии

- `src/MreEssentials/`: один игрок в голосовании, максимальные навыки, локальное управление и диагностика.
- `src/Teleportation.MRE/`: TPA, прием и отказ через штатные plugin-клавиши 0/1 (Б/Ю по умолчанию), события состояния запросов.
- `src/MreKits/`: `/kit`, `/kits`, сохранение cooldown и безопасная выдача.
- `src/MreInterface/`: права и действия `/admin`, серверные события/истории убийств и фактически нанесенного урона. Графику эта сессия не реализует.
- Серверные настройки: 2 HOME обычному игроку, delay HOME 10 секунд, loot зомби 100%, полное качество без износа, полные магазины при появлении с обычным расходом патронов.
- Сохранение, резервирование, назначение подтвержденного владельца, установка DLL и перезапуск MRE после готовности админской части.

## Область UI-сессии

В рабочей папке появились `src/MreHud/`, `ui/` и `scripts/Build-MreHud.ps1`. Серверная сессия их не изменяет, не удаляет и не включает в свои коммиты. Публикацией этих файлов управляет UI-сессия.

Для UI нужны документированные API событий и проверки прав из серверных плагинов. Подключение кнопок не должно обходить серверную авторизацию, TPA-проверки или cooldown наборов. При появлении фактического API его описание будет сохранено в `docs/SERVER_API_FOR_UI.md`.

## Совместная работа

Изменения добавляются в Git только по явному списку своих файлов; `git add .` не использовать. Чужие незавершенные правки не откатывать. Общие README/статус и серверные конфиги менять с проверкой актуального diff. Перед остановкой, заменой сборок или восстановлением использовать `runtime/.mre-maintenance.lock`; о перезапуске сообщает координатор серверной сессии.

Текущий пользователь подтвердил назначение админки своему активному Steam-аккаунту. Его SteamID хранится только в локальных приватных настройках; публичные шаблоны групп не содержат участников.
